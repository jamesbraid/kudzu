# System call handlers

One entry per handler of the native system call table, in call-number order. The table itself is [syscalls.tsv](inventory/syscalls.tsv); the numbering comparison with public lists is in [syscall-selector-crosscheck.md](syscall-selector-crosscheck.md). Numbers 1000 to 1039 and 1041 to 1116 are covered here, except 1056 (`sysmp`) and 1062 (`fcntl`), which are not done yet; `syssgi` (1040) has its own page in [syssgi.md](syssgi.md).

Evidence: the IP35 kernel of 6.5.30 was read first, then the IP27 and IP30 kernels of 6.5.30. Routine names, addresses and sizes come from the kernel's own debug records; field offsets of the thread, process, credential, file and vnode records come from the same records. Public lists (the NetBSD and Linux IRIX layers, qemu-irix) were used only to see which name and argument order to look for. Nothing here has been checked in 6.5.22: it ships kernel object archives but no linked kernel, so the table and the handlers of that release are still to do (see [open-questions.md](open-questions.md)).

## Conventions the handlers share

- Dispatcher: `syscall` (`6.5.30/unix.IP35`, 0xc000000000255a84, 1380 bytes) subtracts 1000 from the call number and compares it unsigned with the count word at +8 of the ABI's table descriptor; an out-of-range number leaves error 22 for the error routine. Call 1000 reloads the real number from the first saved argument register and dispatches again with the arguments shifted by one. The arguments are copied from the saved registers to the thread's argument area (thread record +1032): the first eight registers for the 64-bit and N32 ABIs (ABI bits 0xc), the first four plus 32-bit loads from the user stack for o32. Established.
- Handler signature, as every handler below uses it: `a0` points at the argument area, `a1` at a two-doubleword return area, `a2` is the call number minus 1000. An `int` argument is the low word of its doubleword, so argument N is at +8N and an `int` one is read at +8N+4 (open reads its mode at +20, creat its mode at +12). A pointer or 64-bit argument is read at +8N. The handler's return value is the error number, 0 for success. Established.
- On success the dispatcher stores the first return doubleword in the saved `v0` slot (exception frame +368), clears the error flag slot (+408) and stores the second doubleword in the saved `v1` slot (+376), unless the table entry's first flag byte has bit 0x10 set (no entry in 1000 to 1039 has it). A nonzero error goes to `postsyserrors` (0xc000000000255914, 368 bytes), which stores the error in the saved `v0` slot and sets the error flag slot to 1, with these exceptions: an error of 27 first calls `sigtopid` with signal 31 unless the entry's first flag byte has bit 0x40 (open and creat have it); an error of 1600 calls `vm_pool_retry_syscall`, and if that returns nonzero the saved program counter (frame +648) is backed up by 8 so the call runs again, otherwise the error becomes 11; an error of 4 is stored as 4, but when the thread's flag word (+132 of the thread record) has any of bits 0x1010 the error flag slot is left as it was; an error of 1101 is stored as 11. Established.
- A word at gp+11556 and one at gp-23488 are global switches. The first, when nonzero, turns on the audit hooks (`sat_*` routines) the handlers call after the real work. The second, when nonzero, makes the handler take a read lock on the target's behaviour chain around each virtual-operation call. Neither changes a return value. Inferred.
- Error numbers are written as numbers. The conventional names (1 EPERM, 3 ESRCH, 4 EINTR, 9 EBADF, 11 EAGAIN, 12 ENOMEM, 13 EACCES, 14 EFAULT, 20 ENOTDIR, 22 EINVAL, 29 ESPIPE, 79 EOVERFLOW) are from published headers and are a hint, not read from the binary.
- Calling "the virtual operation at +N" means the handler loads a pointer to a table of function pointers from the first behaviour descriptor of the vnode (vnode +96), the vproc (vproc +40) or the file (file +0), takes the table from descriptor +16 and calls the pointer at +N. The XFS table (`xfs_vnodeops`, 0xc0000000015ea818) names the vnode slots: +24 read, +32 write, +56 getattr, +72 access, +208 seek. The process-operation slots (+16 get process, +32 set nice, +40 set directory, +56 get attributes, +184 set uid, +216 set process group) come from the debug record of `vproc_ops`.
- IP27 and IP30 compared with IP35: for each routine the instruction sequence was compared with call targets resolved by name and the gp-relative and thread-record displacements masked. Where nothing else differs the entry says "same on IP27 and IP30". The record that starts the thread record (`kthread`) is 768 bytes on IP35 and 752 on IP27 and IP30, so thread-record fields sit 16 bytes higher on IP35 (the vproc pointer is at +776 there and +760 on the others). IP30 differs from IP27 further inside the record (the current-directory field is at +1120 on IP30 and +1128 on IP27). These displacement differences, and the per-processor record offsets at absolute addresses, are the only differences noted below unless an entry says otherwise.

- Socket handlers (1089 to 1107): `getvsock` (`6.5.30/unix.IP35`, 0xc0000000001bc030, 76 bytes) takes a descriptor and a pointer for the result. `getf` maps the descriptor and its error is returned; a file whose flag word (+36) lacks bit 0x200 gives 95; otherwise the pointer at +48 of the file record (the socket record) is stored through the result pointer and 0 is returned. Every socket handler below except `socket` begins with it, then reaches the socket's operations the way the vnode handlers do: the first doubleword of the socket record points at a behaviour descriptor, descriptor +16 is the table, and the slot is called with the descriptor as its first argument. The slot offsets come from the debug record `vsocket_ops` (192 bytes): 0 `vs_position`, 8 `vs_create`, 16 `vs_close`, 24 `vs_abort`, 32 `vs_send`, 40 `vs_sendit`, 48 `vs_receive`, 56 `vs_recvit`, 64 `vs_accept`, 72 `vs_listen`, 80 `vs_connect`, 88 `vs_connect2`, 96 `vs_bind`, 104 `vs_shutdown`, 112 `vs_getattr`, 120 `vs_setattr`, 128 `vs_ioctl`, 136 `vs_select`, 144 `vs_getsockname`, 152 `vs_setfl`, 160 `vs_getpeername`, 168 `vs_fstat`, 176 `vs_fcntl`, 184 `vs_pathconf`. Established. `sockargs` (`6.5.30/unix.IP35`, 0xc0000000001bbe28, 188 bytes) takes an output pointer, a user address, a length and a buffer type. A length of 0 or above 224 returns 22 (for type 12 the second check is on the length divided by 4, times 8). Otherwise `m_get` is called with 1 and the type, the length halfword at +24 of the new buffer is set, `bsd_copyin` copies the user bytes to the buffer's data area (buffer +8 added to the buffer address), and on a copy error `m_free` releases the buffer and the copy error is returned; on success the buffer pointer is stored through the output pointer and 0 is returned. The result of `m_get` is not tested on this path. Established for type 8; the code after 0xc0000000001bbee4 belongs to a different routine and was not read as part of it.
- A third global word at gp+11552 is tested by `readlink` (before `mac_vaccess` runs on the looked-up vnode) and by `symlink` (before `mac_initial_path` runs on the link path). The names suggest a mandatory-access-control switch; what sets it was not followed. Same position on IP27 and IP30 up to the gp displacement. Inferred.

## Entries

- `nosys` (`6.5.30/unix.IP35`, 0xc000000000255fe8, 88 bytes). Call numbers 1000, 1007, 1014, 1018, 1028, 1031, 1032, 1048, 1058 and 1074 point here in the native table, and 1075, 1076 and 1078 as well in the `irix5_64_sysent` table, with no arguments. (Later numbers also use it; this page lists them as they come.) It takes the caller's process id (the word at +16 of the thread's vproc pointer, or `kthread_get_pid` when there is no thread or vproc), calls `sigtopid` with that id, signal 12 and mode 2, and returns 22. So an unimplemented call signals the caller and fails with error 22. Number 1000 is the indirect call and is handled in the dispatcher before this point, so only 1007 onward reach it in practice (Inferred for that last remark). Same on IP27 and IP30. Established.
- `rexit` (`6.5.30/unix.IP35`, 0xc0000000002b94e4, 40 bytes), call 1001, one argument. Calls `exit` with 1 as the first argument and the status word at argument +4 as the second, then returns 0 if `exit` comes back. `exit` (0xc0000000002b950c, 816 bytes) was not read in full; that it ends the process is inferred from the name and from its audit and accounting calls. Same on IP27 and IP30. Inferred.
- `fork` (`6.5.30/unix.IP35`, 0xc0000000002e9fac, 40 bytes), call 1002, no arguments. Calls the static `dofork` (0xc0000000002eaab8, 176 bytes) with zeros for the other arguments. `dofork` adds one to the word at +116 of the usage record that the pointer at absolute address -15088 names (the dispatcher adds one to +92 of the same record on every call; that this is a per-process usage record is inferred), calls the static `procfork` (0xc0000000002eab68, 1216 bytes, not read) with a pointer to a local word, and stores that word as the first return doubleword. On success the second return doubleword is 1 when the local word is 0 and 0 otherwise, so the child sees 0 and 1 and the parent sees the child's id and 0. On failure it still stores the word and returns procfork's error. With auditing on, `dofork` reports the result through `sat_fork`. Same on IP27 and IP30 except the accounting record's address. The first flag byte of the table entry is 0x04; nothing read in the dispatcher or error routine uses that bit. Inferred.
- `read` (`6.5.30/unix.IP35`, 0xc0000000002a5460, 28 bytes), call 1003, three arguments: descriptor (+4), buffer (+8), byte count (+16). Calls `_read` with a third argument of 0. Same on IP27 and IP30. Established.
- `_read` (`6.5.30/unix.IP35`, 0xc0000000002a4fb8, 1192 bytes), the common body of read. `getf` maps the descriptor; its error is returned. Paths: a count below zero returns 22; a file whose flag word (+36) lacks bit 0x1 returns 9; with the positioned flag (third argument 1) and a vnode of type 6 it returns 29; a vnode of type 1 with bit 22 of its flag word set returns 13. A file with bit 0x200 set in its flag word is read through the behaviour chain of the object at file +48 (table slot +48); otherwise the vnode's read slot (+24) is called through the vnode's behaviour chain, after `set_ioflags` (0xc0000000002a4f24) turns file flag bits into I/O flags. The count moved is stored in the first return doubleword, added to two counters at +1176 and +1184 of the thread record and to the word at +152 of the usage record named by the pointer at absolute address -15088. A short transfer with error 4 is turned into success. The vnode call is bracketed by calls into the file's own behaviour table (slots +16 or +32 before, +24 or +40 after, not decoded). Audit hooks `sat_check_event` and `sat_fd_rdwr` run when auditing is on. The meaning given to types 1 and 6 comes from the published vnode type list and is a hint. Same on IP27 and IP30 except displacements. Established for the sequence, Inferred for the type names.
- `write` (`6.5.30/unix.IP35`, 0xc0000000002a5960, 28 bytes), call 1004, three arguments laid out as read. Calls `_write` (0xc0000000002a5498, 1224 bytes) with a third argument of 0. `_write` has the same shape as `_read` (same getf, flag and virtual-operation structure, calling slot +32 of the vnode table for the vnode path and slot +32 of the file's own table) but was read only through its vnode call, so the error list is not given. Same on IP27 and IP30 except displacements. Inferred.
- `open` (`6.5.30/unix.IP35`, 0xc0000000002a49a8, 56 bytes), call 1005, three arguments: path (+0), flags (+8), mode (+20). Calls `copen` with the path, the flags plus the 32-bit constant 1 (the literal 0xffffffff00000001 at gp+3496, added as a 32-bit sum, which turns the user's access mode into the internal read and write bits), the mode and the return area. Same on IP27 and IP30. Established.
- `creat` (`6.5.30/unix.IP35`, 0xc0000000002a4c34, 44 bytes), call 1008, two arguments: path (+0), mode (+12). Calls `copen` with flags 770 (0x302) and that mode. Which bits 0x302 sets is inferred from the published open flag list (write, create, truncate). Same on IP27 and IP30. Inferred.
- `copen` (`6.5.30/unix.IP35`, 0xc0000000002a4c60, 608 bytes), shared by open and creat. Returns 22 if the low two flag bits are both clear. If flags & 0x84 is 0x84 it clears bit 4 (the value 0x4). `vfile_alloc` reserves a file slot and descriptor with flags & 0x790ff; its error is returned. `vn_open` then opens the path with the flags and mode & 0xfff; for a write open the handler calls `getfsizelimit` first and passes 6 instead of 4 as vn_open's seventh argument when the limit is 0. If the vnode returned has bit 0 of its flag word set, the new slot is undone, the vnode's device minor is taken, the vnode is released, and the open proceeds as a clone: for a vnode of type 4 the minor number is treated as a descriptor (`getf`) and duplicated with `fdt_dup`; for other types it returns 22. Otherwise `vfile_ready` publishes the file and the descriptor is stored in the first return doubleword. An error of 13 triggers `sat_access` when auditing is on, and `sat_open` runs after success or failure. Same on IP27 and IP30 except displacements. Established for the sequence, Inferred for the clone meaning.
- `close` (`6.5.30/unix.IP35`, 0xc0000000002a4ec0, 100 bytes), call 1006, one argument: descriptor (+4). `closefd` removes the descriptor and yields the file; its error is returned. `vfile_close` then releases the file and its result is the return value; `sat_close` records it when auditing is on. Same on IP27 and IP30. Established.
- `link` (`6.5.30/unix.IP35`, 0xc0000000002a6954, 44 bytes), call 1009, two arguments: existing path (+0), new path (+8). Calls `vn_link` with both paths and two zeros, and returns its result. No audit hook in the handler. Same on IP27 and IP30. Established.
- `unlink` (`6.5.30/unix.IP35`, 0xc0000000002a6c78, 140 bytes), call 1010, one argument: path (+0). With auditing on it first calls `sat_pn_book`. `vn_remove_audit_extended` removes the name (zeros for the other selectors, a local audit buffer pointer last); `sat_access` runs after when auditing is on; the audit buffer is freed with `kern_free` if one was made. The result of the remove is returned. Same on IP27 and IP30. Established.
- `exec` (`6.5.30/unix.IP35`, 0xc0000000002f4138, 40 bytes), call 1011, two arguments: path (+0), argument vector (+8). Calls `iexec` (0xc0000000002f41b0, 548 bytes) with the path, the vector and 0 for the environment. `iexec` was not read; the name and the zero third argument suggest that the environment is taken from elsewhere, which is not confirmed. Same on IP27 and IP30. Inferred.
- `chdir` (`6.5.30/unix.IP35`, 0xc0000000002a5f78, 504 bytes), call 1012, one argument: path (+0). `lookupname` follows the path (flag 1) to a vnode; its error is returned. A vnode whose type (+32) is not 2 is released and the call returns 20. The vnode's access slot (+72) is then called with mode 64 and the current credential; a failure releases the vnode and is returned. On success the vproc's set-directory operation (slot +40) is called with the vnode, the address of the thread's current-directory field and 2; the thread record holds that field at +1136 on IP35, +1128 on IP27 and +1120 on IP30. With auditing on, `sat_pn_book` runs first and `sat_check_event`, `sat_chrwdir` or `sat_access` afterwards. Type 2 is the published directory type (hint). Same on IP27 and IP30 except displacements. Established for the sequence, Inferred for the type name.
- `gtime` (`6.5.30/unix.IP35`, 0xc0000000002b4ff4, 52 bytes), call 1013, no arguments. Calls `microtime` into a local pair and stores its word at +4 as the low word of the first return doubleword. Returns 0. That the word is the whole seconds of the current time is inferred from the name. Same on IP27 and IP30. Inferred.
- `chmod` (`6.5.30/unix.IP35`, 0xc0000000002a8c64, 136 bytes), call 1015, two arguments: path (+0), mode (+8). Builds an attribute record whose mask word is 2 and whose mode word (+8) is the mode & 0xfff, then calls `namesetattr_audit_extended` with the path, 1 (follow links), the record, 0 and a local audit buffer pointer. `sat_chmod` records the call when auditing is on and the buffer is freed. Returns the result of the set. Same on IP27 and IP30. Established.
- `chown` (`6.5.30/unix.IP35`, 0xc0000000002a8d74, 240 bytes), call 1016, three arguments: path (+0), user (+8), group (+16). A user or group below -1 or above 0x7fffffff returns 22. The attribute record's mask word gets 4 when the user is not -1 and 8 when the group is not -1; the user goes at record +12 and the group at +16. Then the same `namesetattr_audit_extended` call as chmod; `sat_chown` runs when auditing is on. Returns the result. The bit values 4 and 8 are the published user-id and group-id attribute bits (hint). Same on IP27 and IP30. Established for the sequence, Inferred for the bit names.
- `sbreak` (`6.5.30/unix.IP35`, 0xc00000000029214c, 184 bytes), call 1017, one argument: new break (+0, 64-bit). `as_lookup_current` finds the address space; the handler calls the operation at +72 of the table reached through +32 of the address-space record, with the pointer stored at local +8 by `as_lookup_current`, 1 and the new value, loops while the result is 1600 and `vm_pool_wait` succeeds, turns a failed wait into 11, and calls `nomemmsg` when the final error is 11. Returns the final error. That the operation adjusts the break is inferred from the name; the table was not decoded. IP27 and IP30 differ by one instruction: after the retry branch IP35 reloads the address-space pointer from the stack in the branch delay slot, and the others do not (the loop reloads it at its head anyway). Inferred.
- `lseek` (`6.5.30/unix.IP35`, 0xc0000000002a73e0, 144 bytes), call 1019, three arguments: descriptor (+4), offset (+8, 64-bit), whence (+20). Saves the ABI word from `get_current_abi`, calls `do_lseek` with the descriptor, a pointer to the offset and the whence. On success, when ABI bit 0x2 is set (the o32 ABI, by the dispatcher's use of the mask 0xc for the other two) and the new offset exceeds 0x7fffffff it returns 79; otherwise the new offset is stored in the first return doubleword. In the `irix5_64_sysent` table the entry's first flag byte is 0 where the native table has 0x08; what the bit means was not found. Same on IP27 and IP30. Established for the code, Unknown for the flag bit.
- `do_lseek` (`6.5.30/unix.IP35`, 0xc0000000002a7074, 724 bytes). `getf` failure is returned. A file with bit 0x200 set in its flag word returns 29. Otherwise it calls the file table slot +16 for the current position, then by whence: 0 uses the offset as given; 1 adds it to the position and returns 79 if a positive offset gives a negative sum; 2 calls the vnode getattr slot (+56) with mask 128, adds the size (record +40) and stores it; any other value calls `sigtopid` with signal 12 and returns 22. The new offset is stored through the pointer, then passed with the old position to the vnode seek slot (+208) and, if that returns 0, to the file table slot +24. Negative results for whence 0 and 2 are not rejected here. Audit calls `sat_fd_read` and `sat_check_event` run when auditing is on. Same on IP27 and IP30 except displacements. Established.
- `getpid` (`6.5.30/unix.IP35`, 0xc0000000002b54dc, 104 bytes), call 1020, no arguments. The first return doubleword is the word at +16 of the thread's vproc pointer (or `kthread_get_pid` when the thread or vproc is missing); the second is the word at +672 of the process record (`p_ppid`). The first value is read as the process id but its field name was not read. Returns 0. Same on IP27 and IP30 except displacements. Established for the loads, Inferred for the first value's meaning.
- `mount` (`6.5.30/unix.IP35`, 0xc000000000289e8c, 32 bytes), call 1021, six arguments. Calls `cmount` (0xc000000000289eac) with the argument area, the return area and two zeros. `cmount` was not read. Same on IP27 and IP30. Inferred.
- `umount` (`6.5.30/unix.IP35`, 0xc00000000028a008, 664 bytes), call 1022, one argument: path (+0). `lookupname` follows the path; its error is returned. If bit 20 of the vnode's flag word is set the vnode is a mount root: the file system record (vnode +48) gets its unmount operation (slot +32 of the table reached from +104, `fs_dounmount` in the XFS table) called with the vnode and the credential; a nonzero result is returned, otherwise `vfs_deallocate` frees the record. If the bit is clear and the vnode type is 3, `vfs_busydev` finds the file system mounted from that device and the file system record's slot +48 (named root in the XFS table) is called with the address of the local that held the vnode, and the unmount then runs on that file system; any other type releases the vnode and returns 22. Hooks at gp+9952, gp+9944 and gp+9928 run before and after when set; what they are was not read. Same on IP27 and IP30 except displacements. Inferred.
- `setuid` (`6.5.30/unix.IP35`, 0xc0000000002b50bc, 80 bytes), call 1023, one argument: user id (+4). A negative value returns 22. Otherwise the vproc's set-uid operation (slot +184) is called with -1, the id and 1, and its result is returned. The meaning of -1 and 1 is not read. Same on IP27 and IP30 except displacements. Inferred.
- `getuid` (`6.5.30/unix.IP35`, 0xc0000000002b51b0, 56 bytes), call 1024, no arguments. `get_current_cred` gives the credential; the first return doubleword is its real user id (+16) and the second its effective user id (+8). Returns 0. Same on IP27 and IP30. Established.
- `stime` (`6.5.30/unix.IP35`, 0xc0000000002b5028, 148 bytes), call 1025, one argument: new time in seconds (+4). `cap_able` with the mask 0x8000000 decides permission; without it the call returns 1. With it the thread is pinned with `setmustrun` to the processor number at gp+10288, `settime` is called with the time and 0, `wtodc` writes the clock chip, `restoremustrun` unpins, and `sat_clock` records it when auditing is on. Returns 0. Same on IP27 and IP30. Established.
- `ptrace` (`6.5.30/unix.IP35`, 0xc00000000026dd08, 716 bytes), call 1026, four arguments: request (+4), process (+12), address (+16), data (+24). Request 0 or below sets a flag in the caller's process flag word (+656, `bitlock_set` with 1 and 2) and returns 0. A positive request finds the target with `ptrsrch` (returns 3 if there is none), gets its process record through the vproc operation at +16 and returns 1 if the record's word at +160 has bit 0x80. If the switch at gp+11552 is set `mac_access` is asked, and a refusal returns 13. The target thread's flag word (+832 on IP35) must have bit 0x10, else the call returns 3. The request fields are then written into a shared record under a global mutex, the target is put back on the run queue, the caller sleeps on the record, and the result stored in the record is returned in the first return doubleword. A negative status from the record returns 5. The target is always released with `vproc_release`; `sat_ptrace` records the result when auditing is on. Same on IP27 and IP30 except displacements. Inferred.
- `alarm` (`6.5.30/unix.IP35`, 0xc0000000002b65f8, 348 bytes), call 1027, one argument: seconds (+4). Under the process's timer lock (+2144), `chktimeout_tick` and `tick_to_timeval` turn any pending timeout into a remaining time, the pending timeout is cancelled with `untimeout` (waiting with `untimeout_wait` if it is running and retrying), the alarm fields at +2116 to +2136 and +2180 are cleared, the requested seconds are stored at +2132, and a nonzero request is converted with `hzto` and armed with `timeout`, whose id is stored at +2180. The first return doubleword is the word at local +4 (the seconds `tick_to_timeval` produced), raised to 1 when that word is 0 and the doubleword at local +8 is nonzero. Returns 0. The field offsets are process-record offsets from the thread's process pointer; the process record has no fields of those names read in the debug data. Same on IP27 and IP30 except displacements. Established for the sequence, Inferred for the rounding's purpose.
- `pause` (`6.5.30/unix.IP35`, 0xc0000000002b6754, 112 bytes), call 1029, no arguments, first flag byte 0x80. Loops: locks the current thread's flag word (+132) with `mutex_bitlock` and sleeps with `sv_bitlock_wait_sig` on the variable at +184 of the record that the pointer at absolute address -16352 names, and repeats until the sleep's result is -1. The loop ends on that result and the handler returns 4. The code has no other exit, so the call returns only after a signal interrupts the sleep. Same on IP27 and IP30. Established.
- `utime` (`6.5.30/unix.IP35`, 0xc0000000002a978c, 260 bytes), call 1030, two arguments: path (+0), time pair pointer (+8). With a null pointer both times come from `nanotime_syscall` (seconds only) and the last argument to the set routine is 0. Otherwise `bsd_copyin` reads 8 bytes (two 32-bit seconds, access then modification); a failed copy returns 14. The attribute record gets mask 768, the access time at +48 and the modification time at +64 (microseconds zero), and the last argument becomes 1. `namesetattr_audit_extended` is called with the path, 1, the record, that flag and an audit buffer pointer; `sat_utime` records it when auditing is on. Returns the result of the set or 14. Same on IP27 and IP30. Established.
- `access` (`6.5.30/unix.IP35`, 0xc0000000002a7470, 768 bytes), call 1033, two arguments: path (+0), mode (+8). Any bit outside 0x1f returns 22. Bit 0x8 asks for the effective ids to be used; when it is clear the handler copies the credential (`crdup`), sets the copy's effective user and group ids from the real ones and its real ids from the effective ones, installs it with `set_current_cred`, and puts the original back and frees the copy before returning. `lookupname` follows the path; its error is returned. The vnode's access slot (+72) is called with (mode & 7) << 6 and the credential. When bit 0x10 is set and that call succeeded, the getattr slot (+56) is called with mask 2, and a vnode of any type but 1, or a type 1 vnode whose mode word has none of the bits 0x49, returns 13. When (mode & 7) is 0 and the switch at gp+11552 is set, `mac_vaccess` is asked instead of the access slot. Which ids are meant by "real" and "effective" follows the credential field names; the bit meanings of 0x8 and 0x10 are inferred from this behaviour. Same on IP27 and IP30. Established for the sequence, Inferred for the bit meanings.
- `nice` (`6.5.30/unix.IP35`, 0xc0000000002b5bf4, 184 bytes), call 1034, one argument: increment (+4). A value below 0 or above 40 needs `cap_able` with the mask 0x200000000, else the call returns 1. The vproc's set-nice operation (slot +32) is called with the address of a local copy of the increment, the credential and 1; on success the first return doubleword is the local value after the call minus 20, and 0 is returned; on failure the operation's error is returned. Same on IP27 and IP30 except displacements. Established.
- `statfs` (`6.5.30/unix.IP35`, 0xc00000000028ac4c, 276 bytes), call 1035, four arguments: path (+0), buffer (+8), length (+16, 32 bits used), file system type (+24, 32 bits used). With auditing on `sat_pn_book` runs first. `lookupname` follows the path; its error is returned.
