# syssgi selectors

`syssgi` is the IRIX system call that multiplexes machine-specific operations behind one selector number. This page documents the selectors one at a time, starting with the ones that touch NUMA, memory, partitions, timers and the front-panel hardware. The table of every selector the kernels reach is [selectors.tsv](inventory/selectors.tsv); the numbering is compared with public lists in [syscall-selector-crosscheck.md](syscall-selector-crosscheck.md). The public `SGI_*` names below come from NetBSD's IRIX compatibility header and are hints only: each selector is confirmed from the shipped kernels.

Evidence is the 6.5.30 linked kernels `6.5.30/unix.IP27`, `6.5.30/unix.IP30` and `6.5.30/unix.IP35`. The 6.5.22 kernels are not linked in this repository, so nothing here is claimed for them.

## Entry convention and dispatch

The kernel's `syssgi` function receives a pointer to the argument block in its first register and a pointer to the return value in its second: `syssgi` is at 0xc0000000002317e0 on IP27 (12720 bytes), 0xa8000000201eb9a8 on IP30 (11992 bytes) and 0xc0000000002e0310 on IP35 (16704 bytes). The selector is the doubleword at +0 of the block (the `ld` at 0xc000000000231820 on IP27). The user arguments are doublewords at +8, +16, +24 and +32, called `arg1` to `arg4` below; a 32-bit argument is read with `lw` from the low half of its slot (+12, +20, +28), a pointer or 64-bit argument with `ld`. Established for the IP27 case code read below.

IP27 and IP30 dispatch through a table of 1261 doublewords indexed by the selector; a selector of 1261 or more returns 22 (IP27 0xc000000000231848). IP35 uses a compare tree that also reaches selector 8194. The function's return value is an errno number, 0 on success: each case code leaves it in a register that the common exit moves to the return register (IP27 0xc00000000023184c and 0xc000000000231850), and a call that has a result stores it through the second argument.

## Platform differences

- Selectors 195, 212, 218, 231 and 1103 point at the shared default on IP30 (0xa8000000201eba10, which sets 22), so they return 22 there. Selector 1250 points at the shared default on IP27 (0xc000000000231848) and has no row of its own for IP35 in `selectors.tsv`; what IP35 does with it was not read. Established from the case targets in the table.

## NUMA

- `numa_tune` (`6.5.30/unix.IP27`, 0xc0000000002852b0, 1216 bytes): syssgi selector 212 (public name NUMA_TUNE). The case code at 0xc0000000002322fc passes arg1's low word as the command, arg2 as a path pointer and arg3 as a user buffer pointer; the routine's return value is the errno. Commands are 100 (read) and 101 (write); any other command returns 22 (0xc0000000002852e8). A non-zero path is resolved with `lookupname` (call at 0xc000000000285318) before the command is checked; a failure returns the constant 2, not `lookupname`'s value. On success the word at offset 36 of the result goes to `master_node_get` (0xc000000000285330), the result is sign-extended from 16 bits as the node number and the object is released with `vn_rele` (0xc000000000285340). With no path, command 100 uses the halfword at address -15326 (0xffffffffffffc422) as the node and command 101 means all nodes; a node of -1 from the path lookup does the same. Command 100 returns 14 for a zero buffer pointer; otherwise it reads the node's tunables block (the doubleword at address -15360 points to a structure whose first doubleword points to an array indexed by node of node records, and offset 8 of the record is the block), copies 8 bytes from block offset 0 and 48 bytes from block offset 8 into a stack buffer at offsets 4 and 12, and copies 2108 bytes from that buffer to the user pointer with `copyout` (0xc0000000002853f4). The routine's stores into that buffer cover offsets 4 to 59; it returns 14 if `copyout` fails and 0 otherwise. Command 101 calls `cap_able` with 0x2000000 (0xc00000000028540c) and returns 1 when it refuses, returns 14 for a zero buffer pointer or a failed `copyin` of 2108 bytes (0xc000000000285430), and then runs `migr_parms_check` on the block, for the one node (0xc00000000028548c) or for each of `numnodes` nodes in turn (0xc000000000285468), returning the first non-zero result. It then stops memory ticking on the target node or on every node in turn with `mem_tick_quiesce_node` (0xc0000000002854c8, 0xc00000000028550c); if a node refuses it re-enables the nodes already stopped with `mem_tick_reactivate_node` (0xc0000000002854e4) and returns 16. It copies the same 8 and 48 byte regions from the user block into each target node's tunables block and stores a doubleword at offset 56 of an uncached block (the stores at 0xc000000000285604 for one node and 0xc000000000285700 for all nodes; the value is the word at offset 16 of the node's tunables block with bit 63 set; the base is the pool word 0x9200000001a00000 at 0xc0000000014cc1f8 plus a halfword looked up in a table by node number and shifted left 32). The one-node store sits in the delay slot of the call to `mem_tick_init_node` (0xc000000000285600), so it runs before that call; `mem_tick_reactivate_node` (0xc000000000285608) follows and the routine returns 0. Which hardware register the offset-56 store reaches and what the tunable fields mean are unknown; no field names appear in the binary. Inferred.
- `numa_tune` (`6.5.30/unix.IP35`, 0xc000000000330cf8, 836 bytes): selector 212, case code at 0xc0000000002e1508, same arguments and commands as IP27. The path lookup, node resolution, buffer checks, `cap_able` (0xc000000000330e54) and `copyin` are as on IP27, with the default node taken from the halfword at address -15318 (0xffffffffffffc42a) and the node count from the word `numnodes` (gp+10276). The routine never calls `mem_tick_quiesce_node`, `mem_tick_init_node` or `mem_tick_reactivate_node` and never makes the offset-56 store: command 101 validates with `migr_parms_check`, copies the two regions into the node blocks (a loop ending in the branch-likely `bnel` at 0xc00000000033102c for all nodes) and returns 0. Inferred.
- `numa_stats_get` (`6.5.30/unix.IP27`, 0xc00000000026d748, 192 bytes): selector 218 (NUMA_STATS_GET). The case code at 0xc0000000002322d8 passes arg1 as a path pointer and arg2 as a user buffer pointer. A zero path returns 22 (0xc00000000026d780). The path is resolved with `lookupname` (0xc00000000026d768), a failure returns the constant 2, the word at offset 36 of the result goes to `master_node_get` (0xc00000000026d790), the object is released with `vn_rele` (0xc00000000026d79c), and a node of -1 after sign extension from 16 bits returns 22. A zero buffer pointer returns 14. Otherwise 208 bytes are copied with `copyout` (0xc00000000026d7e8) from the block whose pointer is at offset 24 of the node record (the record is found as in `numa_tune`); a `copyout` failure returns 14, success 0. What the 208 bytes contain is unknown. Established.
- `numa_stats_get` (`6.5.30/unix.IP35`, 0xc00000000031c3c0, 192 bytes): selector 218, case code at 0xc0000000002e212c. Its instructions match the IP27 routine's once addresses and gp offsets are masked (compared by instruction text), and the callees are the IP35 copies of `lookupname`, `master_node_get`, `vn_rele` and `copyout`. Like the IP27 routine it returns 22 for a zero path or a node of -1, returns 2 when the lookup fails, returns 14 for a zero buffer pointer or a failed copy, and returns 0 on success. Established.
- `numalinkstats_up2date` (`6.5.30/unix.IP27`, 0xc00000000001b0fc, 164 bytes): called by syssgi selector 231 (public name ROUTERSTATS_ENABLED). The case code at 0xc000000000232068 passes the constant 600 as the argument, stores the result as a word on the stack, copies 4 bytes to the pointer in arg1 with `copyout` (0xc00000000023207c) and returns 14 if `copyout` returned a negative value, else 0. The routine walks, for each of `numnodes` nodes, the singly linked list whose head is the doubleword at offset 18808 of the node record (the link is at element offset 32); for each element it follows the pointer at element offset 24 when it is non-zero and keeps the largest doubleword at offset 48 of what that pointer addresses. It returns 1 when that maximum plus the argument times 1250000 (0x1312d0, formed at 0xc00000000001b108) is not below the doubleword read from the uncached address 0x9200000001030100 (the pool word at 0xc0000000014cc150), and 0 otherwise (unsigned compare). Reading the uncached doubleword as a free-running counter and 1250000 as its rate in ticks per second is the reasoning (it matches the 800 ns period `query_fasttimer` returns on this platform); the register is not identified. Inferred.
- `numalinkstats_up2date` (`6.5.30/unix.IP35`, 0xc0000000000424c4, 224 bytes): selector 231, case code at 0xc0000000002e1eb8, same wrapper as IP27. The list walk is the same except that the head is at offset 34280 of the node record (0x10000 added, then -31256) and the node count is `numnodes` (gp+10276). The rate is not a constant: the routine reads the doubleword at the uncached address 0x9200000001604200 (pool word at 0xc000000001644050), forms a period ((value >> 4) & 0x3ff) * 10 + 10 and divides 1000000000 by it (`ddiv` at 0xc000000000042578, with a trap on a zero period at 0xc000000000042594). It returns 1 when the maximum plus the argument times that quotient is not below the doubleword at the uncached address 0x9200000001030100 (pool word at 0xc000000001644048), else 0. The meaning of the two uncached reads is not established. Inferred.
- `numa_tests` (`6.5.30/unix.IP27`, 0xc000000000283998, 896 bytes): selector 1103 (NUMA_TESTS). The case code at 0xc000000000231b34 passes arg1's low word as the command, the low halfword of arg2 (offset 22 of the block) as a node number and arg3 as the user buffer pointer. Command 200 copies the word `numnodes` to the user buffer (`copyout` at 0xc000000000283af4), returning 14 on failure and 0 otherwise. Commands 201 and 202 return 22 for a node of -1; otherwise, with no range test on the node, they read a doubleword from entry `node` of a table of 136-byte entries (the table pointer is the doubleword at offset 1544 of the structure the address -15360 points to), at entry offset 128 for command 201 and 120 for command 202, form the 32-bit value ((x >> 14) & 0x3fc0000) | (((x & 0xffffffff) + 0xfffffffffe800000) >> 6) and copy 4 bytes to the user buffer (`copyout` at 0xc000000000283a50 and 0xc000000000283abc), returning 14 on failure and 0 otherwise. Command 203 copies 1028 bytes in (0xc000000000283b1c), runs four passes over the nodes (at most 64) that each store one 4-byte value per node at block offset 4 + pass*256 + node*4, and copies 1028 bytes back (0xc000000000283c40), returning 14 on a failed copy. Command 204 copies 24 bytes in (0xc000000000283ad4), looks an object up with `curpmo_ns` (0xc000000000283c54) and `pmo_ns_find` (0xc000000000283c68) by the word at offset 0, returns 3 when none is found, returns 22 after calling the object's method at offset 8 when the word at object offset 24 is not 1, and otherwise writes a 24-byte reply (the result of `mld_getnodeid` at offset 4, the halfword at object offset 34 at offset 8, the doubleword at object offset 40 at offset 16), copies it out (0xc000000000283ccc), calls the method at object offset 8, and returns 14 if the copy failed, else 0. Any other command returns 22. The values in commands 201 to 203 are not decoded here. Inferred.
- `numa_tests` (`6.5.30/unix.IP35`, 0xc00000000032f2d8, 568 bytes): selector 1103, case code at 0xc0000000002e1e80. Commands 200, 201, 202 and 204 behave as on IP27, with the table pointer at offset 1512 and the 32-bit value formed as ((x >> 14) & 0x3f80000) | (((x & 0x1ffffffff) + 0xfffffffffe000000) >> 6) (instructions 0xc00000000032f35c to 0xc00000000032f384). There is no case for command 203: it returns 22 with every other unlisted command. Inferred.

## Partitions and placement objects

- `part_operation` (`6.5.30/unix.IP27`, 0xc0000000003c23e4, 8 bytes): called by syssgi selector 195 (PART_OPERATIONS). The case code at 0xc0000000002323ec passes arg1's low word, arg2's low word, arg3, arg4 and the return pointer. The body is `jr ra` with 89 set in the delay slot, so the call always returns 89 and ignores its arguments. Established.
- `part_operation` (`6.5.30/unix.IP35`, 0xc0000000004965c4, 8 bytes): selector 195, case code at 0xc0000000002e10e0, the same two instructions, so it returns 89. Established.
- `pmoctl` (`6.5.30/unix.IP27`, 0xc000000000283d60, 788 bytes): selector 208 (PMOCTL). The case code at 0xc000000000232324 passes arg1's low word as the command, arg2 and arg3, and the return pointer. A command of 62 or more takes the default, which calls `pmo_checkerror` with -4. Otherwise it jumps through the 62-doubleword table at 0xc0000000003f03b0; the delay slot of that jump (0xc000000000283d90) loads 65 into the register that later holds the status. `pmo_checkerror` (0xc000000000283d18, 72 bytes) returns 0 for a non-negative argument; for a negative one it searches 25 pairs of words, from the pointer at gp-4104, for the argument and returns the paired word, or 22 when absent. Cases that produce a handle store the callee's 64-bit result through the return pointer and pass its low 32 bits to `pmo_checkerror`; the other cases pass the callee's result to it directly. The commands are: 1 `pmo_xface_mld_create` (handle); 2 `pmo_xface_mld_destroy`; 3 `pmo_xface_mld_create` (handle); 4 `pmo_xface_mld_place`; 10 `pmo_xface_mldset_create` (handle); 11 `pmo_xface_mldset_destroy`; 12 `pmo_xface_mldset_place` (handle); 13 returns 89 with no call; 14 `pmo_xface_mldset_create` (handle); 20 `pmo_xface_pm_create` (handle); 21 `pmo_xface_pm_destroy`; 22 returns 65 with no call; 23 `pmo_xface_pm_attach`; 24 `pmo_xface_aspm_getdefaultpm` (handle); 25 `pmo_xface_pm_getpmhandles` (handle); 26 `pmo_xface_pm_stat`; 27 `pmo_xface_pm_set_pagesize`; 28 `pmo_xface_aspm_setdefaultpm`; 29 `pmo_xface_pm_create` (handle); 30 `pmo_xface_process_mldlink`; 40 `migr_xface_migrate`; 41 `pmo_xface_as_migrate`; 42 `pmo_xface_as_migrate_close`; 50 `pmo_xface_get_pginfo` (handle); 51 `pmo_xface_mld_getnode` (handle); 60 `pmo_xface_aspm_getcnodemask` (handle, no arguments); 61 `pmo_xface_aspm_setcnodemask` (handle, one argument from arg2). Every other command takes the default. The callees were not read, so the meaning of what the cases pass is unknown. Established.
- `pmoctl` (`6.5.30/unix.IP35`, 0xc00000000032f558, 1064 bytes): selector 208, case code at 0xc0000000002e0620, the same call as IP27. The table has 103 doublewords at 0xc0000000004d47a8 (a command of 103 or more takes the default, 0xc00000000032f590). Commands 1 to 61 reach the same callees as IP27 with these differences: command 61 passes `pmo_xface_aspm_setcnodemask` a two-doubleword mask, arg2 and zero (0xc00000000032f61c), where IP27 passes one doubleword; command 60's callee returns two doublewords and the first is stored through the return pointer (IP27 stores the callee's single result). Three commands are new. Command 100 stores 16 through the return pointer (0xc00000000032f600) and returns 0. Command 101 returns 12 when arg3 is below 16 (`sltiu` at 0xc00000000032f5ec); otherwise it calls `pmo_xface_aspm_getcnodemask`, copies 16 bytes to the pointer in arg2 with `copyout` (0xc00000000032f948), returns 14 on failure, and on success stores 0 through the return pointer and returns 0. Command 102 returns 12 when arg3 is below 16; otherwise it copies 16 bytes in from the pointer in arg2 with `copyin` (0xc00000000032f904), returns 14 on failure, calls `pmo_xface_aspm_setcnodemask` (0xc00000000032f96c) with the two doublewords read, ignores its result, stores 0 through the return pointer and returns 0. Commands 1 to 59 were compared with IP27 by callee name and address only. Inferred.

## Memory and translation

- Selector 1011 (PHYSP), IP27 case code at 0xc000000000231d04: masks arg1 with -16384, passes that address, the constant 4, a stack buffer and the constant 8 to `vtop`, gives errno 22 when it yields 0, and otherwise copies 4 bytes from the stack buffer to the pointer in arg2 (copy call at 0xc0000000002333d4), with errno 14 on failure and 0 otherwise. The IP30 and IP35 case code is at 0xa8000000201ebeec and 0xc0000000002e1b98. Established from the case code.
- `vtop` (`6.5.30/unix.IP27`, 0xc0000000001e2f7c, 32 bytes): a wrapper that hands its four arguments and two zeros to `vtopv` (call at 0xc0000000001e2f88) and returns its result. The IP30 (0xa8000000201a6b68) and IP35 (0xc000000000292e00) routines are the same eight instructions with addresses masked. Established.
- `vtopv` (`6.5.30/unix.IP27`, 0xc0000000001e2f9c, 112 bytes): saves its arguments on the stack, asks `as_lookup_current` (0xc0000000001e2fc4) for the current address space into the slot at sp+32, takes the doubleword at +32 of that result, loads a method pointer from the doubleword at (the doubleword at +16 of that object) + 136, and invokes it (0xc0000000001e2ff0) with the address as its third argument, 4 as its fourth, 2 as its fifth, the stack record at sp+0 as its sixth and zero as its seventh. It returns 1 when the method returns 0, else 0. The method was not identified, so what the 4 bytes of the selector's result mean is not established; reading them as a physical page number follows only the public name. Inferred.
- `sgi_symtab` (`6.5.30/unix.IP27`, 0xc0000000001d026c, 356 bytes): called by syssgi selector 106 (SYMTAB). The case code at 0xc000000000232a78 passes arg1's low word as the command, arg2 and arg3. Commands 6 and 8 allocate 128 bytes with `kern_malloc` (0xc0000000001d02e0) and call `get_current_abi`; when bit 4 of its result is clear they return 37, otherwise they copy a string in from arg2 with `copyinstr` (0xc0000000001d0310), look it up with `st_findaddr` (0xc0000000001d0334), return a non-zero status from it, and otherwise copy the 8-byte result out to arg3 with `copyout` (0xc0000000001d0350), returning 35 if that copy fails and 0 otherwise; the buffer is freed with `kern_free` (0xc0000000001d0320) on every path. Commands 7 and 9 return 37 when the same ABI bit is clear, otherwise copy 8 bytes in from arg3 with `copyin` (0xc0000000001d02c8, a failure returns 35), look the address up with `st_findname` (0xc0000000001d0370) and return a non-zero status from it, return 3 when the name's length plus one exceeds 128 (the `sltiu` at 0xc0000000001d0390), and otherwise copy the name with its terminator to arg2 with `copyout` (0xc0000000001d03b8), returning 10 if that copy fails and 0 otherwise. Any other command returns 32. `st_findaddr` and `st_findname` (0xc0000000001d03d0 and 0xc0000000001d048c, 188 bytes each) were not read, so the table they search is inferred from their names. The same instruction sequence (addresses masked) is in IP30 and IP35, with case code at 0xa8000000201eca68 and 0xc0000000002e2d00. Inferred.
- `sgi_mconfig` (`6.5.30/unix.IP27`, 0xc0000000001d0118, 340 bytes): called by syssgi selector 69 (MCONFIG). The case code at 0xc000000000232d38 passes arg1's low word as the command, arg2, arg3's low word (offset 28 of the block) and the return pointer. Commands 1 to 4 call `cap_able` with 0x2000000000 (1 shifted left 37, at 0xc0000000001d01c0) and return 1 when it refuses. Commands 1 to 3 then return 38 when the word `mloaddebug` (gp-26704) equals 0xdead; otherwise command 1 calls the routine at 0xc0000000001d07fc with arg2, command 2 calls 0xc0000000001d098c with arg2 and 0, and command 3 calls 0xc0000000001d0e34 with arg2. Command 4 returns 38 on the same test and otherwise calls 0xc0000000001d1068 with arg2. Command 5 makes no capability check and calls 0xc0000000001d12c8 with arg2, arg3's low word and the return pointer. Command 6 stores arg2 into `mloaddebug` (0xc0000000001d0254) and returns 0. Any other command returns 31. The five called routines have no symbols and were not read, so what the commands do is unknown; the name of `mloaddebug` suggests module loading. The same instruction sequence (addresses masked) is in IP30 and IP35, with case code at 0xa8000000201ecd28 and 0xc0000000002e2ae8. Inferred.

## Timers, clocks and the front-panel LEDs

- `query_cyclecntr_size` (`6.5.30/unix.IP27`, 0xc000000000045e60, 8 bytes): called by syssgi selector 165 (CYCLECNTR_SIZE). The case code at 0xc000000000232624 stores the returned value as a doubleword through the return pointer (0xc00000000023262c) and returns 0. The body is `jr ra` with 64 set in the delay slot. The IP30 and IP35 routines (0xa800000020014fac and 0xc000000000067c6c, 8 bytes each) are the same two instructions. Established.
- `query_fasttimer` (`6.5.30/unix.IP27`, 0xc000000000045e58, 8 bytes): called by syssgi selector 166 (QUERY_FASTTIMER). The case code at 0xc000000000232610 stores the returned value as a doubleword through the return pointer and returns 0. The body is `jr ra` with 800 set in the delay slot, so the call returns 800. Established.
- `query_fasttimer` (`6.5.30/unix.IP30`, 0xa800000020014f8c, 32 bytes): selector 166, case code at 0xa8000000201ec600. The routine returns 1000000000 divided by the word `fasthz` (gp-29836), with a trap on a zero divisor (0xa800000020014f9c). Established.
- `query_fasttimer` (`6.5.30/unix.IP35`, 0xc000000000067c48, 36 bytes): selector 166, case code at 0xc0000000002e1f1c. The routine loads the doubleword at the uncached address 0x9200000001604200 (pool word at 0xc000000001644050) and returns ((value >> 4) & 0x3ff) * 10 + 10; which register sits there is unknown. Established.
- `gettimetrim` (`6.5.30/unix.IP27`, 0xc000000000047120, 8 bytes): called by syssgi selector 54 (GETTIMETRIM). The case code at 0xc000000000232fe0 stores the returned word on the stack, copies 4 bytes to the pointer in arg1 with `copyout` (0xc000000000232ff4) and returns 14 if `copyout` returned non-zero, else 0. The body is `jr ra` with a load of the word `timetrim` (gp-29820) in the delay slot. The IP30 and IP35 routines (0xa800000020015e34 and 0xc000000000068d04) are the same pair on their own `timetrim`. Established.
- `settimetrim` (`6.5.30/unix.IP27`, 0xc0000000000470a4, 124 bytes): called by syssgi selector 53 (SETTIMETRIM). The case code at 0xc000000000233008 brackets the trim between `setmustrun` (given the halfword `clock_processor`, gp+7360) and `restoremustrun` (given the saved record) and passes the trim's result back as the errno. The routine calls `cap_able` with 0x8000000 (0xc0000000000470b4) and returns 1 when it refuses, returns 22 when the argument is below -3000000 (`slt` at 0xc0000000000470cc) or above 3000000 (0x2dc6c0, `slt` at 0xc0000000000470dc), and otherwise takes the spin lock at gp+2508 with `mutex_spinlock_spl` (0xc0000000000470f8), stores the argument into `timetrim` (0xc000000000047104), releases the lock with `mutex_spinunlock` (0xc000000000047108) and returns 0. The IP30 and IP35 routines (0xa800000020015db8 and 0xc000000000068c88, 124 bytes each) are the same sequence, with only the lock's gp offset differing. What `timetrim` adjusts is not established. Established.
- `setmustrun` (`6.5.30/unix.IP27`, 0xc000000000192664, 344 bytes): used by selector 53's case code to pin the calling thread to the clock processor while the trim is stored. The argument is the processor number. The routine reads the current thread pointer from the doubleword at address -16352. Only when the byte at thread offset 112 is 1 and the byte at offset 848 is not 255 does it call `xthread_table_capable` (0xc000000000192768); a zero result skips the change (read-only path, 0xc000000000192778 to 0xc0000000001927b8). Otherwise it takes the bit lock on the word at thread offset 132 with `mutex_bitlock` (0xc0000000001926a4), saves the halfword at thread offset 122 and replaces it with the argument, calls `rt_rebind` (0xc000000000192750) when bit 0x1000 of the word at offset 132 is set, the halfword at offset 120 is not -1 and differs from the new offset-122 value, sets bit 0x20000 of that word (0xc000000000192744) if it was clear, releases the lock with `mutex_bitunlock` (0xc000000000192704), and calls `qswtch` with 1 (0xc000000000192730) when the processor halfword at address -15328 is not the new one. It returns a doubleword record: the first four bytes hold 1 when bit 0x20000 was already set, and the halfword at +4 holding the thread's offset-122 value from before the call. `restoremustrun` (0xc0000000001927bc, 232 bytes) was not read. The IP30 and IP35 routines are at 0xa80000002015b284 and 0xc0000000002404d8, 344 bytes each, with the same instruction sequence except the fixed addresses and thread offset 864 on IP35. Inferred.
- Selector 7 (SETLED), IP27 case code at 0xc0000000002331a8: checks capability bit 0x2000000000 (1 << 37) with `cap_able` (0xc0000000002331ac), gives errno 1 when it refuses, otherwise passes arg1's low word to `sys_setled` (0xc0000000002331bc) and gives 0. The IP35 case code (0xc0000000002e1da0, after a selector compare that gives 22 on a mismatch) makes the same check and call (0xc0000000002e1dac, 0xc0000000002e1dbc). The IP30 case code at 0xa8000000201ed198 has no capability check: it calls `sys_setled` with arg1's low word and gives 0. Established from the case code.
- `sys_setled` (`6.5.30/unix.IP27`, 0xc00000000004370c, 28 bytes): a wrapper that calls `set_leds` (0xc000000000043714) and returns its result. The IP30 (0xa80000002001288c) and IP35 (0xc000000000064a28) routines are the same shape around their own `set_leds`. Established.
- `set_leds` (`6.5.30/unix.IP27`, 0xc000000000043690, 124 bytes): stores its argument as a word at address -15084 (0xffffffffffffc514) and tests the byte at address -15069 (0xffffffffffffc523). With the byte non-zero it stores the argument, zero-extended, as a doubleword at the uncached address 0x9200000001a20080 plus the slice number from `get_slice` shifted left 5 plus the node number from `get_nasid` shifted left 32; with the byte zero it does the same with base 0x9200000001a20050 and the slice shifted left 3. Which per-node register those addresses are and what the byte selects are unknown. Inferred.
