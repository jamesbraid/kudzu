# Kernel tracing, loadable modules and runtime code patching

What the 6.5.30 kernels already provide for observing themselves, what their module loader does, and what the binaries say about changing kernel code at run time. IP35 (Origin 300/350, Onyx 300/350) is read first and IP27 (Origin 200/2000, Onyx2) is compared in each entry and in the [last table](#ip27-against-ip35). Evidence is `6.5.30/unix.IP35` and `6.5.30/unix.IP27` (linked 64-bit images with DWARF), the relocatable `idbg.o` and `idbgstubs.a` in `IP35boot` read by symbol table and strings only, and the 6.5.22 `var/sysgen.IP35` configuration files (`master.d`, `system/irix.sm`). Symbol names are those of the kernels' own symbol tables or DWARF. Public `syssgi` names come from the public lists in [syscall-selector-crosscheck.md](syscall-selector-crosscheck.md) and are hints for finding a selector; the number and the handler are what the binary shows.

Grades follow [AGENTS.md](../AGENTS.md): **established** is read in the binary, **inferred** says what it rests on, **unknown** says what would settle it. Statements about how an R10000 behaves (cache operations, TLB entry bits, instruction fetch) rest on general knowledge of the architecture, no manual page was checked for this page, and they are graded inferred wherever they go beyond the instruction constants in the kernel. Userland tools for this area (`par`, `ml`, `lboot`, the crash-dump analyser, the PCP kernel agent) are not held in `root/`, so nothing here describes them.

Related pages: [module-interfaces.md](module-interfaces.md) (the object format and relocation kinds the loader accepts, the kernel calls a module can use, interrupt-context rules and the processor event-counter path, which this page does not repeat), [syssgi.md](syssgi.md) (selectors 69 and 106), [syscalls.md](syscalls.md), [klconfig.md](klconfig.md) (kernel text replication), [sysgen.md](sysgen.md) (what a kernel is configured with), [kernel-debug-signatures.md](kernel-debug-signatures.md), [ip35-panic-support.md](ip35-panic-support.md).

## What the shipped kernels are built with

The kernel's observability depends on which modules `lboot` linked in. The shipped `unix.IP35` and `unix.IP27` carry the stub modules and not the debugger, which is what the 6.5.22 default `system/irix.sm` (the only one held; there is no 6.5.30 `var/sysgen`) selects. That the 6.5.30 kernels were linked from the same default is inferred from the kernels agreeing with it (the debugger stubs, the lock-statistics stub and the absent `ktrace` names below).

The 6.5.22 `var/sysgen.IP35/system/irix.sm` names the stub modules `prfstubs` and `idbgstubs` (among others) in a `USE:` line at line 505. At lines 746 to 761 it `EXCLUDE`s `idbg`, `mloadidbg`, `disp_idbg` and the other `*idbg` modules, and at line 762 it says `USE: prf`. The comment at lines 742 to 745 says that for most users only the first `EXCLUDE` line needs to change to `INCLUDE` to configure the kernel debugger, and the comment at lines 764 to 771 gives an alternative `LDOPTS` line, with the layout file `sn1_elspec.dbg`, for a kernel that can coexist with `symmon`, the PROM-resident monitor. The IP27 `irix.sm` has the same `EXCLUDE: idbg` line (line 741) and `USE: prf` (line 755). Established, as a statement about the configuration files; the linked kernels agree (next items).

The linked kernels contain the stub form of the debugger. The real debugger, `idbg.o` and the `*idbg` modules, is the optional subsystem `eoe.sw.kdebug` on the installation media; the 6.5.30 IP35 `irix.sm` additionally excludes the debugger modules by name (line 804 and following) and says in a comment that `kmem_debug` needs that subsystem, so two independent reasons keep it out of the shipped kernels (inferred for the missing install). `idbg_setup` (`6.5.30/unix.IP35`, 0xc00000000021e208, 56 bytes) loads a table pointer from the doubleword `idbgfuncs` (0xc00000000163d0a0) and calls through it; `idbg_tablesize`, `idbg_copytab`, `idbg_dofunc`, `idbg_error`, `idbg_switch`, `idbg_addfunc` and `idbg_delfunc` (0xc00000000021e240 to 0xc00000000021e318, 36 bytes each) do the same at offsets +0x18, +0x10, +0x20, +0x28, +0x30, +0x38 and +0x40. The initial value of `idbgfuncs` is `idbgdefault` (0xc00000000163b6e0): a version word of 1, then stub routines starting at 0xc000000000497b4c that return, return 0, or call `nodev` (the entries for `idbg_copytab` and `idbg_dofunc` call `nodev`). IP27 has the same stubs (`idbg_setup` at 0xc0000000001736a0, 56 bytes, `idbg_dofunc` at 0xc000000000173720, 36 bytes). Established.

`idbgstubs.a` in `IP35boot` defines `idbgdefault` and the `_idbg_*` stub names; `idbg.o` (a relocatable object of about 988 KB) defines the real `_idbg_setup`, `_idbg_dofunc`, `_idbg_switch`, `_idbg_utrace` and the `ktrace_first`, `ktrace_next`, `ktrace_nentries` and `ktrace_skip` buffer walkers. None of the `ktrace_*` names, and no `ktrace_alloc` or `ktrace_enter`, is in either linked kernel's symbol table, so the per-subsystem `ktrace` buffers that the debugger can walk appear to be compiled out of the shipped kernels. Inferred: the symbol tables hold no local symbols (5029 functions are known only from debug information), so the absence of a global name does not rule out a static buffer type, and the kernel strings still name a trace-buffer header. Established that the global names are absent.

- `lstat_user_command` (`6.5.30/unix.IP35`, 0xc0000000002372fc, 8 bytes; IP27 0xc000000000189378, 8 bytes) is two instructions that return the constant 1008 (0x3f0), so the lock-statistics command reached from `sysmp` does no work in the shipped kernels and reports a fixed code; why that code was chosen is unknown. `master.d` ships `ksync_statistics` as an alternative module excluded by default. The real lock-statistics code, `ksync_statistics.a`, is on the media in the base subsystem (not an optional one); the 6.5.30 IP35 `irix.sm` selects the plain `ksync` at line 691 and its comments (lines 595 to 600 and 670 to 674) say to swap it, with `hardlocks_statistics`, to collect statistics, so this stub is a configuration choice. Established for the stub; inferred for the reason.

`kdebug` (halfword at 0xc00000000163d3da on IP35, 0xc0000000014cb9da on IP27) holds 0xffff in the file, that is -1. `debug` (0xc00000000006d0ec, 120 bytes) tests that halfword and returns at once unless it is positive. Established; see [the debugger section](#the-kernel-debugger).

`utrace_bufsize` is 0 in the file and `utrace_mask` is 0xfff3f, the same defaults the `mtune` file gives (`utrace_bufsize` 0 with a range of 0 to 0x7fffffff, `utrace_mask` 0xfff3f). With a zero buffer size the timestamp trace described next is off. Established.

## Tracing and instrumentation

### Timestamp trace buffers and utrace

The kernel has one general-purpose event log, a per-processor ring of timestamped records, with a user-space mapping interface and a kernel-side producer.

- `log_tstamp_event` (`6.5.30/unix.IP35`, 0xc0000000002e87ec, 716 bytes) is the event writer; `tstamp_user_create` (0xc0000000002e935c, 276 bytes) and `tstamp_update_mask` (0xc0000000002e9328, 52 bytes) create the buffers and update the mask. `log_tstamp_event` bumps the write index with `atomicIncWithWrap` (call at 0xc0000000002e88f0), reads the status register with `getsr` and tests `issplprof`, raises the priority with `spl1` and restores it with `splx`, and can wake a waiter with `sv_signal` when the buffer fills (calls at 0xc0000000002e8a28 to 0xc0000000002e8a98). So the writer takes no lock and is built to be callable from interrupt context. The routine is the same size on IP27 (0xc000000000238b24, 716 bytes). Established for the calls; the "callable from interrupt context" reading is inferred from the interrupt-priority handling; the lock and interrupt-level rules for module code are in [module-interfaces.md](module-interfaces.md#rules-for-interrupt-context-stacks-and-preemption).
- `utrace_init` (`6.5.30/unix.IP35`, 0xc0000000002e9994, 224 bytes) returns at once when `utrace_bufsize` is 0. For 0x800 it creates a buffer for every processor (`tstamp_user_create`, then `tstamp_set_eob_mode` with mode 1 and `tstamp_update_mask`). For any other value it prints "utrace_bufsize has an invalid value (%d).  Resetting it to %d" with 0x800 and stores 0x800 (0xc0000000002e9a60 to 0xc0000000002e9a70). `_utrace_sanity` (0xc0000000002e98d0, 196 bytes) stores a new `utrace_mask` and calls `tstamp_update_mask` under `mrlock`. Established. IP27: `utrace_init` 0xc000000000239ccc, `_utrace_sanity` 0xc000000000239c08, same sizes.

`utrace_trtbl` (`6.5.30/unix.IP35`, 0xc000000001598588) is a table of event codes and names, all `TSTAMP_EV_...`: interrupt entry and exit, event-interrupt entry and exit, end-of-dispatch, end-of-switch (plain and real-time priority), start of major and minor tick, user-level interrupt, yield, the CPU, RTC and profile counter interrupts, group interrupt, timeout, and CPU and network interrupt. Established. The debugger's `utrace` command ("Latest UTRACEs for all CPUs", "Set utrace mask", "Find utrace entry") is in `idbg.o` only.

User-space control is the `RT_TSTAMP_*` family of `syssgi` selectors (public names; 122 to 128, 144 and 145). On IP35, selectors 123, 125, 127 and 145 share one case that calls `syssgi_tstamp` (0xc0000000002e5c4c, 520 bytes); on IP27 all of 122 to 128, 144 and 145 share the case at 0xc000000000232918, which calls `syssgi_tstamp` (0xc000000000235f84, 520 bytes). The other IP35 selectors in the family have their own case code that was not read. Established for the shared cases.

Producers read so far:

- `syscall` (`6.5.30/unix.IP35`, 0xc000000000255a84, 1380 bytes) logs one event for each system call entry and exit when `utrace_bufsize` is non-zero and bit 2 of `utrace_mask` is set: the loads of those two globals are at 0xc000000000255ef0 and 0xc000000000255efc, and the two `log_tstamp_event` calls (0xc000000000255f44 and 0xc000000000255fa0) both pass event code 0xf618. Established. IP27's `syscall` is 0xc0000000001a6ea4, 1440 bytes; its hook sites were not compared.

The interrupt-time producers are `cpuintr` (0xc000000000060890, calls `log_tstamp_event` at 0xc000000000060970 and 0xc000000000060990), `doactions` (0xc000000000294908, call at 0xc0000000002949c4) and `cpuaction` (0xc000000000294ae0, call at 0xc000000000294c08); they log the interprocessor-call events. Established.

### Hooks on the system call path

`syscall` has these call sites around the handler (addresses are the call instructions). The audit hooks first:

- `sat_init_syscall` (`6.5.30/unix.IP35`, 0xc000000000496fd8) and `sat_check_flags` (0xc000000000497000), the audit (`sat`) hooks, at 0xc000000000255e4c and 0xc000000000255e94.

`presysactions` (`6.5.30/unix.IP35`, 0xc0000000002551f0, 656 bytes) before the handler and `postsysactions` (0xc000000000255480, 1172 bytes) and `postsyserrors` (0xc000000000255914, 368 bytes) after it (calls at 0xc000000000255df8, 0xc000000000255de8 and 0xc000000000255e38). `presysactions` calls `remove_bp`, `stepoverwatch`, `blockme`, `stop` and `prsright_release`; `postsysactions` calls `clrsyswatch`, `prfault`, `profileregion`, `psig`, `stop`, `install_bp` and `prsright_obtain_self`. These are the points where a process stops for the debugger interface described in the next section, where user breakpoints (`install_bp`, `remove_bp`, 0xc000000000254adc and 0xc000000000254c98, 328 and 180 bytes) are inserted and removed, and where watchpoints are stepped over. Established for the calls; the purposes are inferred from the names and from the `/proc` handlers that share them (`prsright_*`, `stop`).

`fawlty_sys` (`6.5.30/unix.IP35`, 0xc00000000008fe88, 52 bytes) and `fawlty_sysend` (0xc00000000008febc, 72 bytes), called at 0xc000000000255ee0 and 0xc000000000255e84 when bit 0x100 of a word at offset 0x290 of a per-process record is set (the loads are at 0xc000000000255e5c and 0xc000000000255ec8). Each forwards to `sysrec` (0xc00000000008ff04, 864 bytes) with event code 0xea76 (entry) or 0xea77 (exit). `sysrec` calls `getargsize`, `isinputarg` and `copyin` to copy the arguments of the call, and `log_tstamp_vevent` (0xc0000000002e8ab8, 1168 bytes) to write them into the timestamp buffers described above. The decoders `select_decode` (0xc000000000090264), `fcntl_decode` (0xc000000000090298), `poll_decode` (0xc0000000000903b4), `rwv_decode` (0xc0000000000903d4) and `ioctl_decode` (0xc000000000090418) are next to it. So this is a system call recorder that stores calls with their decoded arguments in the same per-processor buffers as utrace. The same module records process creation and exec (`fawlty_fork` 0xc00000000009083c, called from `procfork` and `nsproc_common`; `fawlty_exec` 0xc0000000000908c0, called from `iexec`), context switches (`fawlty_resched` 0xc000000000090960, called from `swtch`, `istswtch` and `xthread_epilogue`) and disk requests (`fawlty_disk` 0xc000000000090a64, called from four `dksc` routines). Established.

The recorder is switched on from the profiler device: `prfioctl` (0xc00000000008e7b8, 520 bytes) calls `fawlty_control` (0xc00000000008fd80, 264 bytes) at 0xc00000000008e8ec, `fawlty_start` (0xc00000000008fb94, 192 bytes) at 0xc00000000008e99c and `fawlty_stop` (0xc00000000008fcf8, 136 bytes) at 0xc00000000008e9b0. `fawlty_control` calls `cap_able`, `vproc_lookup`, `bitlock_set` and `bitlock_clr`, so it sets and clears a per-process bit by process id; `fawlty_start` calls `cap_able`, `vproc_lookup`, `fawltyscan` (0xc00000000008faf0) and `procscan`, so it turns recording on for a process or for every process. The command numbers are decoded from the compare tree (`6.5.30/unix.IP35`, 0xc00000000008e7b8 to 0xc00000000008e8c0 and the arms after it; Established): 1 returns the profiler state word with its 0x2000 bit cleared; 2 returns a second state word; 3 reconfigures the profiler from its argument (low byte 0 to 12, bits 8 to 11 zero or 0x100 or 0x200; any other value gives 22; it needs the state word's 0x1000 bit, else the error 1310; an unchanged configuration is a no-op); 0x6d (109) sets a limit word to the argument clamped to 4096, with a negative argument giving 0; 0x6e (110) is `fawlty_stop` and takes a 16-byte request copied in (14 on a fault); 0x6f (111) is `fawlty_control(pid, 0)`, which sets the per-process recording bit for the process id in the argument (0 means the caller), and 0x70 (112) is `fawlty_control(pid, 1)`, which clears it; both need the capability tested by `cap_able` with mask 0x10000000 and return 1 without it; 0x80, 0x100, 0x180, 0x200, 0x280, 0x300 and 0x380 are `fawlty_start` with a 16-byte request, where the command's bit 0x80 adds the start flag 256, bit 0x100 the flag 16 and bit 0x200 the flag 512 (so the seven values are the non-empty combinations of three selector bits); every other command number gives 22. What the three selector bits and the limit word mean, and what the configuration modes 0 to 12 sample, was not read (they are consumed by `prfintr` and `fawltyscan`); the `hwperf_*` calls further down in the same routine belong to its sampling-mode setup, not to a command number.

No `ktrace` is linked in the shipped kernels (see above), no probe facility is linked under any name found in the symbol table (as [module-interfaces.md](module-interfaces.md) also records), and no profiling prologue is linked: neither symbol table has an `_mcount`; the only name that contains `mcount` is `dms_get_itemcount`. Established from the symbol tables. No static table of trace points was found.

### The /proc controls

The `/proc` file system is the kernel's own breakpoint, system-call-trace and fault-trace interface for a process. `prioctl` (`6.5.30/unix.IP35`, 0xc000000000434478, 1928 bytes) prepares the target with `prioctl_prepare` and dispatches to one routine per request; the long requests are in `prioctl_thread` (0xc000000000434c00, 4500 bytes). The routine names are the kernel's own and spell out what each request does.

The requests group as follows: run control and stops: `prioctl_piocrun`, `prioctl_piocwstop`, `prioctl_piocthread`; signal trace and signal delivery: `prioctl_piocstrace`, `prioctl_piocgtrace`, `prioctl_piockill`, `prioctl_piocunkill`, `prioctl_piocaction`; system call entry and exit sets: `prioctl_piocsentry_exit` (0xc0000000004332f8, 444 bytes) and `prioctl_piocgentry_exit` (0xc0000000004331d0, 296 bytes); fault trace: `prioctl_piocsfault` and `prioctl_piocgfault`; mode flags: `prioctl_piocset`, `prioctl_piocreset`; credentials, usage and node: `prioctl_pioccred`, `prioctl_piocgroups`, `prioctl_piocusage`, `prioctl_piocnice`, `prioctl_piocgetnode`, `prioctl_piocgetptimer`, `prioctl_piocacinfo`; per-process hardware event counters: `prioctl_piocenevctrs`, `prioctl_piocenevctrsex`, `prioctl_piocrelevctrs`, `prioctl_piocgetevctrs`, `prioctl_piocsetevctrs`, `prioctl_piocgetevctrl`, `prioctl_piocgetevctrlex`, `prioctl_piocsetevctrl`, `prioctl_piocsaveccntrs`.

All of these except `prioctl_piocsetevctrs` are reached by a direct call from `prioctl` (calls at 0xc0000000004347ac to 0xc000000000434bf0); `prioctl_piocsetevctrs` is called from `prioctl_thread` (0xc000000000434de0). `prioctl` also calls `cap_able_cred` (twice, 0xc0000000004345f8 and 0xc000000000434764) and `ckpt_prioctl`. The counter requests call `hwperf_get_counters` (0xc000000000080038), `piocenevctrsex` and `uthread_apply`, so they use the `hwperf` layer below. Established for the dispatch and the names. [module-interfaces.md](module-interfaces.md) decodes the dispatch (the command minus 0x7102 indexes a 254-entry jump table) and gives the codes of the counter requests (0x71e9 to 0x71f1 and 0x71fc). The codes of the other requests and the meaning of each flag are not decoded here (unknown, see [open questions](open-questions.md)). IP27 has the same routines at different addresses (`prioctl` 0xc00000000035b588, 1968 bytes; `prioctl_thread` 0xc00000000035bd38, 4500 bytes; `prioctl_piocsentry_exit` 0xc000000000359f60, 444 bytes; `prioctl_piocenevctrs` 0xc00000000035a83c, 292 bytes).

The process side of the stop mechanism is `prstop_proc` (0xc00000000042ee20, 572 bytes), `prwstop_proc`, `prfault` (0xc00000000042d988, 976 bytes, called from `postsysactions` at 0xc000000000255574), `prfork`, `prexit`, and `prblocktrace` (0xc00000000042e99c). The routine that actually stops a thread is `stop` (0xc00000000026afe8), which `presysactions` and `postsysactions` call. Established for the calls.

### Counters, profiling and hardware event counters

- `sprofil` (`6.5.30/unix.IP35`, 0xc0000000002b5d20, 1100 bytes) is the system-call profiler behind `profil` (see [syscalls.md](syscalls.md)); `profileregion` (0xc000000000257400, 608 bytes) is called from `postsysactions` at 0xc0000000002556b4 and 0xc000000000255708. `evc_profil` (0xc0000000002b61f8, 1024 bytes), `evc_enable_counters` (0xc0000000002b6194, 60 bytes) and `evc_disable_counters` (0xc0000000002b61d0, 40 bytes) use the hardware counters for profiling. Same sizes on IP27 (`sprofil` 0xc000000000205b54, `evc_profil` 0xc00000000020602c). Established.

The kernel profiler device is `prf`: `prfinit` (0xc00000000008e43c), `prfopen`, `prfclose`, `prfread`, `prfwrite`, `prfioctl` (0xc00000000008e7b8), `prfintr` (0xc00000000008f218) and `prfstacktrace` (0xc00000000008f6b4), with `startprfclk` and `stopprfclk` (0xc0000000000678fc, 0xc00000000006795c) driving the sampling clock and `prfcdevsw` (0xc00000000163bb50) as its character-device switch. `prfioctl` dispatches on the request with a compare tree whose constants are 0x6d to 0x71, 0x100, 0x180, 0x200, 0x280, 0x300, 0x380 and 0x381, and uses `copyin` for 16-byte requests. The configuration file marks it `ocs`, major 7, and `irix.sm` turns it on. Established for the entry points; what each command does is not read except the recorder commands above.

- `hwperf_init` (`6.5.30/unix.IP35`, 0xc00000000007f788, 308 bytes), `hwperf_enable_counters`, `hwperf_disable_counters`, `hwperf_get_cpu_counters` (0xc00000000007ff88, 136 bytes) and `hwperf_overflowed_intr` (0xc00000000007f8bc, 80 bytes) are the R10000 event-counter layer used by the `/proc` counter requests (above). `syssgi` selector 174 (public name EVENTCTR; IP35 case code 0xc0000000002e0f88, which calls the routine at 0xc0000000002e4d2c; IP27 case code 0xc000000000232584, routine 0xc000000000235068) is the system-wide user entry for event counters; its routine was not read, so that it reaches `hwperf` is inferred. Established for the names and the selector; the counter register programming is not read.

### Reading kernel counters from user space

Two kernel services read counters and tables for a monitoring tool; both go through one table.

- `sysmp` (`6.5.30/unix.IP35`, 0xc0000000002ee5a4, 5200 bytes; system call 1056) calls `sysget_mpsa1` (0xc0000000002cb60c, 224 bytes) at 0xc0000000002ef2d4 and `sysget_mpsa` (0xc0000000002cb6ec, 132 bytes) at 0xc0000000002ef2ec. Both call `phost_sysget` (0xc0000000002ca568, 68 bytes), which indexes the table below by an id and calls the handler. Established.
- `sysget` (`6.5.30/unix.IP35`, 0xc0000000002ca5ac, 624 bytes; system call 1226, five arguments) takes an id in the first argument block word, accepts 1 to 38 (otherwise 22), finds the same table at the doubleword at 0xc000000001641ac0 (which holds 0xc0000000015977f8), copies in a 0x4c-byte request, and calls the handler with the id, the user buffers and flags. An entry whose handler pointer is null returns 2, and so does one whose first word is zero (the branch at 0xc0000000002ca604). Established.

The table has 38 entries of 16 bytes (a word, a word of flags, a handler pointer). Thirty entries have a handler: ids 1 to 6, 9, 13 to 18, 20, 21, 23, 24, 31 to 33, 36 and 38 use `sysget_pda` (0xc0000000002ca81c, 1972 bytes), ids 8, 10, 26, 35 and 37 use `sysget_gen` (0xc0000000002cbb30, 796 bytes), id 25 uses `sysget_node` (0xc0000000002cc000, 1100 bytes), id 34 uses `sysget_node64` (0xc0000000002cc44c, 1100 bytes) and id 28 uses `sysget_ksym` (0xc0000000002cbe4c, 436 bytes). Ids 7, 11, 12, 19, 22, 27, 29 and 30 are empty; id 10 has a handler but a zero first word, so `sysget` returns 2 for it as for an empty entry (listed here as populated, not reachable through `sysget`). `sysget_pda` reads per-processor data, `sysget_node` per-node data, `sysget_gen` copies general tables under a mutex through `update_rminfo`; `sysget` itself special-cases id 28 (0x1c) to look a name up with `ksym_find` (0xc0000000002ca438; the call is at 0xc0000000002ca7c0). Established for the table and the handlers' names and callees; what each id returns is not read. The IP27 table (doubleword at 0xc0000000014d0720, table at 0xc00000000146ce88) has the same 22, 5, 1, 1, 1 split and the same empty ids; `sysget_node` and `sysget_node64` are 1092 bytes there.

- `ksym_add` (`6.5.30/unix.IP35`, 0xc0000000002ca2b4, 388 bytes) adds an entry to a private list under a mutex (it initialises two mutexes, named "sgt_ksym" and "sgt_rm64"); `msginit`, `gfxinit`, `udf_init` and `ksym_init` call it. `ksym_find` (0xc0000000002ca438, 140 bytes) finds an entry by name with `strcmp` and prints "ksym_find: %s not found" on a miss. `ksym_init` (0xc0000000002ca4c4, 164 bytes) calls `ksym_add` once and then looks up "tunetable" and "tunename". So the kernel keeps a small private symbol list for `sysget` that is separate from the full symbol table. Established.

A third read path is `syssgi` selector 106 (`sgi_symtab`, [syssgi.md](syssgi.md)): commands 6 and 8 look a name up and return an address, commands 7 and 9 do the reverse, both gated on a bit of `get_current_abi` (the 64-bit ABI). A reader that can read kernel memory could use the returned address. Established for the selector; that a given monitoring agent uses this path is unknown.

Which of these the PCP kernel agent uses, and which ids it reads, cannot be said from the held files. Unknown.

### The kernel debugger

`syssgi` selector 4 (public name IDBG) is the user entry. On IP35 its case code (0xc0000000002e1b28) calls `cap_able` with 0x10000000 and returns 1 when the check fails, then tests the bit with value 4 of the ABI word kept in a saved register (`andi` at 0xc0000000002e1b34; the same test [syssgi.md](syssgi.md) records for the IP27 case, where the word comes from `get_current_abi`) and returns 22 when it is clear (not decoded on IP35, so the ABI reading is inferred there), then switches on the first argument (the compare chain is at 0xc0000000002e1b40 to 0xc0000000002e1b5c): 1 calls `idbg_dofunc` (0xc00000000021e288, call at 0xc0000000002e3138) with the second argument; 2 calls `idbg_switch` (0xc00000000021e2d0, call at 0xc0000000002e3248) with two 32-bit arguments; 3 calls `idbg_tablesize` (0xc00000000021e240, call at 0xc0000000002e2f6c); 0 calls `idbg_copytab` (0xc00000000021e264, call at 0xc0000000002e30d4) with the arguments at +0x10 and +0x1c of the request; anything else returns 22. IP27's case code is at 0xc000000000233228; its body was not compared. Established for IP35. With the stub table, commands 0 and 1 reach `nodev` (the stub entries for `idbg_copytab` and `idbg_dofunc` call it) and the others do nothing, so on the shipped kernels this selector reports no debugger.

A configured debugger registers per-subsystem command functions with `idbg_addfunc` and the `idbg_*` entries named in the symbol tables: examples in the shipped IP35 kernel are `idbg_procscan`, `idbg_pid_to_proc`, `idbg_ncache`, `idbg_dnlc`, `idbg_maddr`, `idbg_mname`, `idbg_rtq`, `idbg_gang`, `idbg_cpuset`, `idbg_xbowregs`, `idbg_nfs` and `idbg_kcdb_dump` (addresses in the symbol table; they are the per-subsystem printers that `idbg.o` and the `*idbg` modules call). The table's capacity is `idbgmaxfuncs`, 0x4b0 (1200) in the file. Established for the names and the capacity. The debugger's own command names are in the data of `idbg.o` and were sampled by `strings` only: they include `ptrace`, `tracemasks` ("Print pr_tracemasks (procfs) struct"), `utrace`, `syscalltrace`, `trace` and the backtrace commands. The full table was not decoded.

- `debug` (`6.5.30/unix.IP35`, 0xc00000000006d0ec, 120 bytes) is the kernel's "enter the debugger" call. When the halfword `kdebug` is positive it executes `break 1` (0xc00000000006d118), then stores 0 to the halfword `kbdstate` (0xc000000001646a12, store at 0xc00000000006d13c) and the byte `kbdcntrlstate` (0xc000000001646a11, store at 0xc00000000006d158), which resets the keyboard driver's state after the debugger has run, and returns. With `kdebug` at -1 it returns at once. Established.
- `VEC_breakpoint` (`6.5.30/unix.IP35`, 0xc00000000006d0e0, 12 bytes) is `j soft_trap`, a delay-slot `nop`, and the word `break 1` at 0xc00000000006d0e8. `handle_brkpt` (0xc000000000063a38, 80 bytes) is in the first-level exception path: it falls to the normal path (`exception+0x268`) for user mode, then loads the instruction at the exception program counter (counter + 4 when the exception was in a branch delay slot), compares it with the word at 0xc00000000006d0e8 and takes the normal path when they differ. When they are equal it stores 1 into a per-processor word of the array at 0xc000000001651640, then loads the doubleword at 0xa800000000001020 (the cached XKPHYS window onto physical address 0x1020) and takes the normal path when it is zero. IP27's `handle_brkpt` is 164 bytes at 0xc00000000003d438. Established up to that load; what a non-zero word leads to was not read.
- `debug_stop_all_cpus` (`6.5.30/unix.IP35`, 0xc000000000060df4, 272 bytes) stops every enabled processor other than the caller, either all of them (first argument -1) or those whose bit is set in the mask it points to, by storing a doubleword of 0x164 or 0x165 (the low bit chosen by `get_cpu_slice`) to a per-node register at offset 0x90 (0x200090 when a bit of the node record is set) of the interrupt block, which is the same register `sendintr` (0xc000000000060824, 108 bytes) writes for an ordinary interprocessor interrupt (`0x9200000001800090` or `0x9200000001a00090`, plus the node number shifted left 33). IP27's `sendintr` writes `0x9200000001800090` plus the node number shifted left 32. Established for the stores; that the register delivers an interrupt is inferred from the name `sendintr`, and its register-level identity is unknown (the node controller datasheets are outside this repository's evidence).
- `install_cpu_nmi_handler` (`6.5.30/unix.IP35`, 0xc0000000000667c8, 192 bytes), `cont_nmi_dump`, `_symmon_dump` (0xc0000000002afdc0) and the data words `dbgmon_symstop`, `dbgmon_nmiprom`, `dbgmon_loadstop` (0xc00000000163d0a8, 0xc00000000163d0ac, 0xc00000000163b790, all 0 in the file) are the hooks for the PROM-resident monitor and the NMI dump; `_j_exceptnorm_nosymmon` (0xc00000000006e050) is the alternative first-level exception stub that does not call the monitor. Established for the names and values; their use is not read beyond the panic path in [ip35-panic-support.md](ip35-panic-support.md).

## Loadable kernel modules

The kernel has its own runtime ELF loader and a registry for four kinds of modules (drivers, STREAMS modules, file systems and Ethernet interfaces) plus three special kinds (the debugger, a library and the kernel's symbol table). The user interface is one `syssgi` selector.

### Entry point

`syssgi` selector 69 calls `sgi_mconfig` (`6.5.30/unix.IP35`, 0xc00000000027fa48, 340 bytes; call at 0xc0000000002e2afc). IP27: 0xc0000000001d0118, 340 bytes, call at 0xc000000000232d44. ### Loading and symbol resolution

- `mload_init` (`6.5.30/unix.IP35`, 0xc00000000027fe78, 692 bytes) finds the file the running kernel came from, because that file is the source of the symbol table. It reads the string `arg_kernname` (0xc0000000016b8af8); if it is empty it prints "Kernname environment variable not set by sash. Runtime symbol table not loaded. Loadable modules will not be registered or loaded." If the first five characters are `bootp` it prints "Cannot load runtime symbol table from bootp'ed kernel. ..." Otherwise it looks for `/unix`, `//unix`, `)unix` or `unix` in the string (`strstr`) to build the path, sets a flag (the word at gp-0x6428), and creates a kernel thread named `munldd` whose entry is the routine `munldd` (`sthread_create`, call at 0xc00000000027ffc0). When a word at gp+0x2a78 equals 1 it uses `/unix` without parsing (0xc00000000027ffec). A kernel started from the network has no loadable modules. Established.
- `mload` (`6.5.30/unix.IP35`, 0xc00000000028012c, 400 bytes) returns 107 (0x6b, at 0xc0000000002802b8) when the kind byte at +0x60 of the record's sub-record is not 7 and both the word at gp-0x6428 (set by `mload_init` when it found the kernel path) and the word at gp-0x6424 are zero. Loading anything but the symbol table therefore needs the kernel path from boot. Established for the branch; the reading of the word at gp-0x6424 is unknown.

`mloadfile` (`6.5.30/unix.IP35`, 0xc0000000002863dc, 104 bytes) calls `mreadfile` (0xc0000000002864b8, 432 bytes), `msetelfsym` and `mreloc` (0xc0000000002863c0, 28 bytes, a wrapper for `doelfrelocs`). `mreadfile` resolves the path with `lookupname` (0xc0000000002864e4), makes two indirect vnode-operation calls (0xc00000000028654c and 0xc000000000286598), releases the vnode with `vn_rele`, and then calls `mreadelfsymtab` (0xc0000000002cd3ac, 960 bytes) or `mreadelf` (0xc0000000002cc898, 2836 bytes); that the first is for the kernel image and the second for a module is inferred from their names. `mreadelf` reads with `vn_rdwr` (fourteen calls between 0xc0000000002cc93c and 0xc0000000002cd18c) into twelve `kern_malloc` and two `kern_calloc` buffers, keys sections by name (`section_key`; it compares section names with `strcmp`, one being `.sdata`) and calls `blkclr` at 0xc0000000002cd1d4. The message "Object file format not ELF" is printed for a file that is not ELF. So the kernel loads an unrelocated ELF relocatable object itself; user space only names the file. Established.

Undefined symbols are resolved against the kernel's symbol table, which is itself a module of kind 7. `mload_rtsyms` (0xc000000000286a70, 680 bytes) takes the symbol table semaphore ("m_trans", `mlsymtabsem`, `mlsymtablock`) and holds the symbol table with `symtab_hold` (0xc000000000285e08); `check_rtsyms` (0xc000000000286d18, 384 bytes) treats `end`, `edata` and `etext` specially; `msetelfsym` (0xc0000000002cd894, 932 bytes) sorts the module's own symbols with `qsort` so `melf_findname` (0xc0000000002cddcc) and `melf_findaddr` (0xc0000000002cdcac) can search them. `mload_auto_rtsyms` (0xc00000000163c754) is 1 in the file. Established for the call structure; the exact lookup order of an undefined symbol (module first or kernel first) was not read. That the table searched is the kernel's own is inferred from the kind-7 loader and the messages.

Relocation is `doelfrelocs` (0xc0000000002cdf84, 1308 bytes). It walks the relocation sections, handles both explicit-addend and implicit-addend forms (`rela_get_addend`, `rel_get_addend`), pairs high and low halves with `find_lo16`, and stores with `extract_relc_val`, `get_target_value`, `fixup` and `put_relc_val`. After the relocation loop it calls `cache_operation` (0xc0000000002b08f0, call at 0xc0000000002ce07c) with an address taken from the object record, a length taken from a section header and the flag word 0x2000, so the module's code is probably made visible to instruction fetch before it runs (inferred from the call and the routine's role). Unsupported relocations print a message with `printf` (calls at 0xc0000000002ce474 and 0xc0000000002ce490). Established for the structure. [module-interfaces.md](module-interfaces.md#relocation-kinds) lists the relocation kinds that `doelfrelocs` accepts and rejects.

The module must carry a string symbol `mversion` equal to "mload version 7.0": `mversion_chk` (0xc000000000286a1c, 84 bytes) looks `mversion` up with `mfindname` and compares. `driver_init` (0xc000000000281be4, 1316 bytes) also calls `mversion_chk` first. Established.

### Init and unload hooks

`driver_init` finds the driver's entry points by building `prefix` + name and looking each up in the module (`mfindname`). The names, in order of the calls, are: `devflag`, `unload`, `unreg`, `reg`, `info`, `attach`, `detach`, `open`, `read`, `write`, `ioctl`, `mmap`, `map`, `unmap`, `poll`, `enable`, `disable`, `size64`, `print`, `dump`, `init`, `close` and `start`; `medtinit` (0xc00000000028349c) handles an `edtinit` routine. `driver_check` (0xc000000000281928) reserves or allocates the major number, `driver_hook` (0xc000000000281a94) allocates the `cdevsw` and `bdevsw` entries and registers the thread priority, `drv_do_load_or_reg` (0xc000000000281228, 520 bytes) ties load and register together, and `drv_unload` (0xc0000000002821a8, 160 bytes) undoes it. When registration fails it prints "Registration failed (%d)" and when unload fails after unregister it prints "Unregistered, but unload failed (%d)". Established.

Auto-load: `clnopen`, `syopen`, `qattach`, `cdrv` (0xc000000000293f38, 840 bytes) and `spec_cs_device_hold` call `cdhold` (0xc000000000283304, 52 bytes); `cdrv` (three call sites, 0xc0000000002941ec, 0xc00000000029420c and 0xc00000000029422c) and `drv_unreg` (0xc0000000002830a8) call `mload_driver_load` (0xc0000000002826a8, 540 bytes). `mload_driver_load` takes the driver semaphore (`psema`, `vsema`), `drv_lock` and `drv_unlock`, loads the module with `mloadfile`, and prints "%s: Failed to dynamically load module. Cannot read or relocate object." or "... no runtime symbol table available." on failure. Established for the call sites. `drvstub_open` and `drvstub_close` (0xc000000000282248, 0xc000000000282498) look like stand-in entries that trigger a load on first open, from their names alone; inferred.

Unload: `munldd` (0xc0000000002833e8, 48 bytes) is the entry of the thread that `mload_init` creates, and `mautounload` (0xc0000000002833c4, 36 bytes) is named for the same job; `module_unld_delay` (0xc00000000163c654) is 5 in the file; `mtimerstart` and `mtimerstop` (0xc000000000283458, 0xc000000000283418) are probably the timer around it (inferred from the names). The command routines call the kind's table methods ([syssgi.md](syssgi.md) lists the IP27 sequences, whose sizes match the IP35 routines): `munload` calls the `unload` method (table offset 16) between the lock and unlock methods (64 and 72), `untimeout` and `freesema`, and releases the record through `freeminfo` (0xc0000000002868b0, 252 bytes); `mregister` calls the `reg` method (offset 24) and `munregister` the `unreg` method (offset 32). Established for IP27 by that page and by equal sizes for IP35; the IP35 instruction match was not rechecked. The unit of `module_unld_delay` is unknown.

The debugger is itself a module kind: `idbg_load` (0xc00000000028543c, 164 bytes) loads the file with `mloadfile` and calls `debug_init` (0xc000000000285004, 728 bytes), which looks up the symbols `_idbg_setup`, `_idbg_copytab`, `_idbg_tablesize`, `_idbg_dofunc`, `_idbg_error`, `_idbg_switch`, `_idbg_addfunc`, `_idbg_delfunc`, `_qprintf`, `__prvn`, `_idbg_late_setup`, `_idbg_unload`, `_idbg_addfssw`, `_idbg_delfssw`, `_printflags`, `_padstr`, `idbg_mrlock` and `_prsymoff` with `mfindexactname` (the strings are at 0xc0000000004cbf28 to 0xc0000000004cc030); `debug_check` (0xc00000000028531c, 288 bytes) compares the module name with `idbg`. These are the names `idbg.o` and `idbgstubs.a` define. So the real debugger object can replace the stubs at run time through the same loader. `idbg_maddr`, `idbg_mname`, `idbg_melfname` and `idbg_melfaddr` (0xc000000000286e98 to 0xc000000000287088) sit in the kernel next to the loader and print module names and addresses; `idbg.o` imports `idbg_maddr` and `idbg_mname`, so the debugger can show loaded modules. Established for the placement and the imports.

### What a module can see

The kernel symbol table is complete for externally visible names only: the `.symtab` of `unix.IP35` has 13043 entries (10102 global functions, 2904 global objects, 2 weak functions, 15 global and 19 local section symbols, one local no-type symbol), and `unix.IP27` has 12043 (9354, 2652, 2, 15, 19, 1). No local function or local object symbol is present. The DWARF information names another 5029 functions in IP35 that have no symbol-table entry (the `dwarf` source rows in [functions.tsv](inventory/functions.tsv)); `mload`, `munload`, `drv_unload` and the other static routines above are of that kind. Whether the loader reads DWARF is not established; `mreadelfsymtab` is named for the symbol table, so a module can bind to a global name only. Established for the counts; inferred for the DWARF point.

Between the two kernels, 11382 global symbol names are common, 624 are only in IP27 and 1624 only in IP35. IP27-only names include the Origin 200/2000 hub workaround routines (`hub_ifdr_check_value`, `hub_ni_vserr`, `hub_slot_get`) and `cache_sync`; IP35-only names include `ctrace`, `hubii_ixtt_get`, `hub_xb_errtype`, `ip35_hub_credit_dwords_max`, `idbg_kcdb_dump` and `kcdb_cachesz`. A module that calls a hub routine therefore binds only on the platform that defines it. Established from the symbol tables.

Structure layouts are not exported with the symbols: a module compiled against the headers must match the kernel's layouts, which differ between IP27 and IP35 for per-node data (the per-node record offsets in [klconfig.md](klconfig.md) change with the NASID shift of 32 against 33). No version check beyond the `mversion` string was found in the routines read (`mversion_chk`, `driver_init`). Established for those routines; the compatibility rule is unknown.

Kernel text and read-only data sit in the write-protected, replicated image (next section), but a module's own sections are read into memory from `kern_malloc` and `kern_calloc` (above), the general kernel heap, so a module is not covered by the wired mapping of the image. Inferred: `mreadelf` calls only those two allocators; the address range that `kern_malloc` returns, and so whether the block is executable at the page level, is not known ([module-interfaces.md](module-interfaces.md) records the same gap).

## Runtime code patching

### What the binaries show

The kernel image is mapped through one wired TLB entry. `mapped_kernel_setup_tlb` (`6.5.30/unix.IP35`, 0xc000000000065538, 168 bytes; IP27 0xc000000000043808, 168 bytes) writes PageMask 0x1ffe000 (a 16 MB page), EntryHi in the xkseg region at virtual address 0xc000000000000000, Index 1, and EntryLo values formed as (physical page frame) | 0x2b for the first page and (frame) | 0x2b | 4 for the second. Bit 2 (the dirty, or write-enable, bit) is clear in the first value and set in the second. The first 16 MB page covers 0xc000000000000000 to 0xc000000000ffffff, which holds `.text` and the first `.rodata` (0xc000000000040000 to 0xc000000000519ebf); the writable `.data`, `.sdata` and `.bss` (0xc000000001519ec0 upward) are in the second page. The routine is called from `start` and `bootstrap` (0xc000000000041b58, 0xc0000000000654bc). Established for the constants and call sites. Inferred: a store to kernel text through its 0xc000... address takes a TLB-modified exception.

Kernel text is replicated per node. `replicate_kernel_text` (0xc000000000074d14, 376 bytes; IP27 0xc000000000050874, 328 bytes), called from `allowboot` at 0xc000000000066090, calls `copy_kernel` (0xc000000000074e8c, 152 bytes) and `set_ktext_source` (0xc000000000074f24, 152 bytes) to copy [0xc000000000040000, 0xc000000000519ebf) (the end is the doubleword at 0xc00000000163e310, the end of the first `.rodata`) with `ovbcopy` into the node's local memory through the cached XKPHYS window (the base 0xa800000000000000 is built by `addiu -0xb`/`dsll32 0x1b`) and records the source node. `ktext_repmask` (0xc000000001652698) holds the nodes that have a copy; [klconfig.md](klconfig.md) has the mask construction and the `numa_kernel_replication_ratio` rule (default 1 in `mtune`, so every node). Established. Consequence for patching: a patch written to one node's copy is not seen by processors executing another node's copy, and the copy that a processor runs from is chosen by the TLB entry written at its start-up. Inferred from the structure; it was not tested.

The kernel itself writes code at run time in one place. `_hook_exceptions` (0xc00000000006dcfc, 836 bytes; IP27 0xc00000000004ccfc, 852 bytes) copies code templates word by word into the per-node vector area through the uncached compatibility window (`lui 0xa000`, so addresses 0xa0000000 and up). The templates are delimited by pointer pairs in the global pointer area: the `utlbmiss_prolog_mp` code (0xc00000000006e08c to 0xc00000000006e09c), the `utlbmiss` code (0xc00000000006e100 to 0xc00000000006e128, with `utlbmissj` at 0xc00000000006e414 to 0xc00000000006e434 as the alternative, chosen by a size test against 0x80 that is inferred to depend on `utlbmiss_prolog_size`) and `utlbmiss_prolog_patch` (0xc00000000006e410, 4 bytes). The routine then calls `flush_cache` (0xc000000000050b84, 40 bytes) at 0xc00000000006e000 and restores the status register (`getsr` and `setsr`, 0xc00000000006e008, 0xc00000000006e018). `utlbmiss_patched`, `need_utlbmiss_patch` and `utlbmiss_prolog_size` (0xc000000001645fac, 0xc000000001645fa8, 0xc000000001644cdc) are its state. Established. This is the shipped model for patching: write through an uncached alias, then flush the caches.

Cache maintenance routines: `cache_operation` (0xc0000000002b08f0, 956 bytes; IP27 0xc0000000002004ac, 1060 bytes) dispatches on a flag word to `_bclean_caches` (0xc0000000002b05c0, 816 bytes), which calls `clean_icache` (0xc000000000067024, 180 bytes) and through it `__pdcache_wbinval`, `__cache_wb_inval`, `__cache_hwb_inval_pfn` and `__picache_inval`. `icache_inval` (0xc0000000002b0ea0, 32 bytes) and `data_cache_operation` and `inst_cache_operation` (0xc0000000002b0e60, 0xc0000000002b0e80, 32 bytes each) are wrappers. `__icache_inval` (0xc0000000000505b0, 136 bytes) is called by the `syssgi` flush-icache case; that case pins the calling thread (`rt_pin_thread`) while it flushes, which flushes only the local processor's instruction cache. `clean_isolated_icache` (0xc0000000002b0480, 320 bytes) takes a semaphore and uses `cpuaction` to run `clean_icache_action` (0xc0000000002b043c, 68 bytes) on each isolated processor. Established for the structure. The meaning of each bit of the flag word (the value 0x2000 is passed by the module loader) comes from a header that is not held (unknown).

Cross-processor calls: `cpuaction` (0xc000000000294ae0, 312 bytes) raises the priority with `spl1`, queues work with `nested_cpuaction` (0xc0000000002949d4, 268 bytes) and the target runs it in `doactions` (0xc000000000294908, 204 bytes), called from `cpuintr` (0xc000000000060890, 272 bytes) after `sendintr` interrupts it; `tlbclean`, `tlbcleansa` and `tlbsync` use the same path. `panicspin` also calls `doactions`. Established.

Breakpoints for user processes are software breakpoints: `install_bp` and `remove_bp` (see the hooks above). The kernel's own breakpoint instruction is `break 1` (word 0x0001000d at 0xc00000000006d0e8), handled as above. Established.

No profiling prologue: neither kernel has an `_mcount` symbol, and 1339 of the 15130 functions in `unix.IP35` are 8 bytes or less (1316 of 8 bytes, two instructions, and 23 of 4 bytes, one instruction). Established from the symbol table and the function table; that there is no padding is inferred from the lack of such a symbol.

### Engineering inference

These points follow from the evidence above and from general knowledge of the processor; none was tested on a running kernel.

To patch kernel text, write through the cached XKPHYS alias of the physical page (the route `copy_kernel` uses), not through the 0xc000... address, then write back the data cache line and invalidate the instruction cache line for the same physical page on the processor that will execute it, as `_hook_exceptions` and `cache_operation` do. With 16 KB pages and the R10000's 16 KB-per-way primary caches, the cache index fits within one page, so the two virtual aliases of a page should index the same cache set. The IP35 `CCOPTS` use `-D_PAGESZ=16384`. Inferred, and not tested.

Text replication means one logical patch is one write per replica. A hook that must be seen everywhere has to patch every node in `ktext_repmask` (and the master's original), or the replication ratio has to be set so only one copy exists. Inferred from the replication code.

Other processors need a stop, a cross-call or hardware coherence: the kernel has `cpuaction` for the first two (it runs at a raised priority in the cross-processor interrupt) and `debug_stop_all_cpus` for a debugger-style stop. Whether the R10000's coherent writes alone invalidate a remote instruction cache line is not shown by any kernel code read here; the kernel's own use of `clean_icache` through `cpuaction` only for isolated processors points to hardware coherence for the others, which is inferred, not established.

Inside a hook, the safe pattern is the one `log_tstamp_event` follows: no blocking, no sleeping locks, an atomic index and a priority that blocks only lower-level interrupts. A probe on a function that runs with interrupts masked cannot use anything that waits. The `break` instruction route goes through `VEC_breakpoint` and `soft_trap` to the C trap handler, which assumes a normal exception frame; the debugger path (`handle_brkpt`) hands off to the monitor instead, so a probe facility would use another break code or its own check. Inferred.

A 4-byte `break` replacing the first instruction of a function works for any function with at least two instructions; for the 1316 two-instruction functions the replaced first instruction (usually a return) would have to be emulated, and a 4-byte `break` cannot be placed in the 23 one-instruction functions without emulating the whole function. There is no padding or profiling prologue to hold an inline jump pair. Inferred.

The module loader is the better delivery path for a probe facility than the debugger: it already relocates against the full global symbol table, runs init hooks, tracks use counts and unloads on a timer, and the loaded section memory is plain heap memory, not the protected image. It does not provide text patching. Inferred.

### Candidate probe points

Probe points that the binaries recommend, because the kernel already instruments them and because the entry and exit are single, well-defined places:

The system call boundary: `syscall` entry and exit (0xc000000000255a84), where the `presysactions`, `postsysactions`, `fawlty_sys` and `fawlty_sysend` hooks and the utrace event already exist. The flag bit 0x100 of the word at offset 0x290 and `utrace_mask` bit 2 enable existing recorders; a new facility could reuse the same buffers (`log_tstamp_vevent`). Established that the hooks exist; the suitability is inferred.

Context switch: `swtch`, `istswtch` and `xthread_epilogue` already call `fawlty_resched`; `TSTAMP_EV_EOSWITCH` and `TSTAMP_EV_EODISP` events exist. Established for the call sites.

Process lifetime: `procfork`, `nsproc_common` and `iexec` call `fawlty_fork` and `fawlty_exec`. Established.

Disk requests: `dkscstrategy`, `dksccommand`, `dkscpurgebp` and `dk_intr` call `fawlty_disk`. Established.

Interprocessor interrupts: `cpuintr` and `doactions` log events. Established.

Poor choices: the exception entry and the TLB miss handlers (`utlbmiss*`, `exception`, `VEC_*`), which are copied into per-node vector areas by `_hook_exceptions`, run before a normal frame exists and are patched by the kernel itself; the 8-byte stubs; anything reached with the status register's interrupt bits cleared that cannot afford a `break`. Inferred.
