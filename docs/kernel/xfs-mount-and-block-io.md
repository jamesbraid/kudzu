# IRIX 6.5.30 XFS mount path, superblock validation, block I/O interface

Area: XFS mount + version + block I/O (questions 4, 5, 6).
Method: binary RE only. Shipped IP35 kernel objects under
`refs/irix-media/6.5.30/usr/cpu/sysgen/IP35boot/` (`xfs.a`, `os.a`, `sgi.a`, `specfs.a`),
the shipped `usr/sbin/lboot` binary, and `var/sysgen/master.d/` config files.
Disassembled with a local capstone script (relocation-annotated, per symbol) and cross-checked
with retools `hostfacts.py` on `xfs_mount_validate_sb`. No IRIX source or headers read.
All prose is my own wording; names are symbols from the objects' own symbol tables.
Work scratch: `/storage/nvme/origami/tmp/irix-kernel-re/work-xfsmnt/` (extracted members, scripts).

## Ground rules and limits (read first)

- There is NO linked `/unix` on the 6.5.30 media. Only relocatable objects (`*.o`, `*.a`) exist.
  So there are no final virtual addresses. Offsets below are function-relative (`func+0xNN`) or
  structure-relative. A live-patch needs the running kernel's symbol table (e.g. `idbg`/`symmon`
  or the booted `/unix`) to resolve `xfs_vfsops`, `vfssw`, `xfs_fstype`, etc.
- The `vfssw[]` table itself is NOT in any shipped object. It is generated by `lboot` at kernel
  link time from the `master.d` files (template strings recovered from the `lboot` binary,
  see Q4). Its entry layout below is inferred from its consumers (`vfsinit`, `vfs_getvfssw`,
  `filesys_insert`) and agrees across all of them.
- The objects carry DWARF1 with function names only (no struct types, no member names). Every
  structure offset below is derived from observed load/store patterns. Field NAMES are my labels,
  marked "label". Offsets are observed facts.
- Cross-check: `6.5-base` (an older release, IP30 `xfs.a`) has a different, older
  `xfs_mount_validate_sb` (details in Q5). Only 6.5.30 is the target.
- Return values: the numeric errnos 0x3f2 (1010) and 0x3f3 (1011) are what the code returns.
  The libc message table has adjacent entries "Filesystem is corrupted" then
  "Mount with wrong filesystem type"; the numeric-to-name mapping is INFERRED from that adjacency,
  not settled from the binary.

## Q4. VFS mount path and fstype switch; where to intercept

### 4.1 Call chain for `mount -t xfs` (all in the kernel, observed)

1. `mount(uap, rvp)` (`vfs.o`, +0x0). A 4-instruction shim: calls `cmount(uap, rvp, 0, 0)`.
2. `cmount(uap, rvp, a2, seg)` (`vfs.o`, +0x20).
   - Resolves the mount-point directory: `lookupname(uap->dir /*uap+0x8*/, seg, FOLLOW=1, NULL, &vp, 0)`.
     Returns the lookup error if it fails. (If auditing is on it books `sat_pn_book` first.)
   - Takes `cred = get_current_cred()` and then dispatches through the covered vnode's
     behavior chain: `vp+0x60` is the vnode's behavior head, its ops pointer is at `+0x10`,
     and the slot at ops+0x168 is the "cover/mount" vnode op. Called as
     `cover(bhv, uap, a2, cred)`. (Cell-enabled kernels wrap this in `bhv_version_read_lock`.)
   - EBUSY (0x10) if the covered vnode fails the mount-point flag test and the update flag is clear.
3. The vnode op at ops+0x168 for an XFS vnode is `fs_cover` (see `xfs_vnodeops` table, Q6).
   It is the generic, filesystem-independent mount engine: `fs_cover(bhv, uap, a2, cred)`
   in `fs_subr.o` (+0x0). `[bhv+8]` is the covered vnode.
   Observed behavior:
   - Marks the vnode "being mounted" (bit 0x200 in `v_flag` at +0x10, via `mutex_bitlock`), fails with
     EBUSY (0x10) if already mounted/mounting.
   - Calls static `getvfsops(uap)` (`fs_subr.o`, +0x554) to pick the vfsops (see 4.2). NULL -> EINVAL (0x16).
   - New mount (uap flag 0x20 clear): `vfs_allocate()` (`vfs.o`, +0x1c6c: `kmem_zalloc(0xb8)`,
     `init_sv`, `bhv_head_init(vfs+0x68)`), then `dnlc_purge_vp(mvp)`, then
     **calls vfsops slot +0x8 as `mount(newvfs, mvp, uap, a2, cred)`** (see 4.3). On success:
     `vfs_add(mvp, newvfs, uap->flags2 /*uap+0x14*/)` (`vfs.o`, +0x1a48) links it into the
     `rootvfs` list and into the covered vnode (`mvp+0x28 = vfsp`, clears the 0x200 mount-in-progress bit).
     On failure `vfs_deallocate(newvfs)`.
   - Remount (uap flag 0x20 set): calls the EXISTING vfs's behavior ops slot +0x18 (`mntupdate`).
   - Before calling the mount slot it copies two 8-byte values from the vfsops trailer into the new vfs
     (+0x88, +0x90) iff the trailer magic matches (see 4.3).
   - Honors `uap->flags & 1` (read-only -> sets `vfs_flag |= 1`), `mac_mount`, `sat_access`, `imon_event`
     (notification hook) as side concerns.
4. `getvfsops(uap)` — the fstype switch (`fs_subr.o`, +0x554, file-local `t`):
   - `uap->flags` (uap+0x10) bits 0x2|0x4 clear -> returns the ops of the root vfs
     (`bhv_base_unlocked(rootvfs+0x68)` -> ops at +0x10), i.e. "same fs type as root".
   - else `fstype = uap->fstype /*uap+0x18, 64-bit*/`:
     - `fstype < 0x100`: used as a small integer INDEX: valid if `0 < fstype < nfstype`; ops =
       `vfssw[fstype].vsw_vfsops`; out of range -> NULL.
     - `fstype >= 0x100`: treated as a USER POINTER to a name string: `copyinstr(ptr, buf, 16)`, then
       `vfs_getvfssw(name)`. This is what `mount -t xfs` ends up doing (name "xfs").
   - `vfs_getvfssw(char *name)` (`vfs.o`, +0x2468) returns `struct vfssw *`: a linear scan of `vfssw[1..nfstype-1]`
     doing `strcmp(name, ent->name)` under `vfsswlock`, skipping empty names. Special-cases the alias "dbg" -> "proc".
     Index 0 is never matched. Returns NULL if absent.
5. `fstype` index of XFS: stored by XFS's own init (4.4) in global `xfs_fstype` (`xfs_vfsops.o`, `B`, int);
   written into every XFS vfs as `vfs+0x34` (see `xfs_get_vfsmount`).

### 4.2 The vfssw table (generated, not shipped; layout from consumers)

Entry stride = 0x30 bytes (6 x 8). Global symbols `vfssw` (array), `nfstype` (int, "count in use"),
`vfsmax` (int, capacity, a tunable listed in `var/sysgen/mtune/kernel`).
Fields observed:

| off  | label            | evidence |
|------|------------------|----------|
| 0x00 | vsw_name (char*) | `vfs_getvfssw` strcmp; `filesys_check` strcmp |
| 0x08 | vsw_init (fn)    | `vfsinit` calls it as `init(&entry, fstype_index)` |
| 0x10 | vsw_vfsops (ptr) | `getvfsops` returns this |
| 0x18 | vsw_vnodeops(ptr)| lboot template + mload fills it from the module's `vnodeops` symbol |
| 0x20 | (pointer; mload sets it to `dead_vnodeops`; meaning not settled) | `filesys_init` |
| 0x28 | (zero; meaning not settled) | `filesys_init` |

`lboot` (shipped binary) template strings: for each module with master flag `j` (file system type) it emits
`extern int PREFIX_init(); extern struct vfsops PREFIX_vfsops; extern struct vnodeops PREFIX_vnodeops;` and an entry
`{ "name", PREFIX_init, &PREFIX_vfsops, &PREFIX_vnodeops, 0, 0 }`, an `{ "BADFS", ... }` filler, a terminating
`{ "", 0,0,0,0,0 }`, then `int nfstype = N; int vfsmax = M;`. XFS's master file is
`var/sysgen/master.d/xfs`: flags `oxj`, prefix `xfs_`, depends `sgi,specfs,io` (j = fs type, o = single spec,
x = configurable object). So the table entry's name is the prefix minus the underscore ("xfs") and the symbols
it binds are `xfs_init`, `xfs_vfsops`, `xfs_vnodeops`.

`vfsinit()` (`vfs.o`, +0x2618): sets `nfstype = vfsmax`... (it loads `vfsmax` into `nfstype` first), inits `vfslock`/`vfsswlock`,
`kmem_zone_init(0x400)` for pathnames, `vn_init`, `dnlc_init`, then for i in `1..nfstype-1` with a non-NULL `vsw_init`:
`vsw_init(&vfssw[i], i)`. So init is called once at boot for each configured fs, with the table index as second arg.

### 4.3 vfsops structure (what `mount` slot is, observed from the `xfs_vfsops` data object)

`xfs_vfsops` (`xfs_vfsops.o`, `.data`+0x18, 152 bytes). 8-byte slots (relocation targets):

| off  | XFS handler | role (label from handler name + observed call sites) |
|------|-------------|---------|
| 0x00 | (header word 0x0004010100000000; meaning not settled) | |
| 0x08 | `xfs_vfsmount`    | MOUNT: called by `fs_cover` for a new mount |
| 0x10 | `xfs_rootinit`    | root-mount init |
| 0x18 | `xfs_mntupdate`   | remount (update) |
| 0x20 | `fs_dounmount`    | generic unmount engine |
| 0x28 | `xfs_unmount`     | filesystem unmount (also called on mount-failure cleanup) |
| 0x30 | `xfs_root`        | get root vnode (called right after mount, `xfs_vfsmount`->`xfs_mount` for dmapi event) |
| 0x38 | `xfs_statvfs`     | |
| 0x40 | `xfs_sync`        | |
| 0x48 | `xfs_vget`        | |
| 0x50 | `xfs_vfsmountroot`| |
| 0x58 | `fs_realvfsops`   | generic |
| 0x60 | `fs_noerr`        | |
| 0x68 | `xfs_quotactl`    | |
| 0x70 | `xfs_force_pinned`| |
| 0x78 | trailer: 32-bit magic 0x18732739 in the high half | `fs_cover` tests `lw [ops+0x78] == 0x18732739` |
| 0x80 | 1 | copied into `vfs+0x88` iff magic matches |
| 0x88 | 2 | copied into `vfs+0x90` iff magic matches |

Behavior ops are invoked as `ops[slot](bhv_or_vfs, ...)`. For the MOUNT slot only, the first argument is
the raw `vfs_t*` (no behavior is attached yet).

**MOUNT slot signature (observed from `fs_cover` caller and `xfs_vfsmount` callee):**

```
int mount(vfs_t *vfsp, vnode_t *mvp, struct mounta *uap, <a3: ignored by XFS>, cred_t *cr);
```
returns 0 or an errno. `xfs_vfsmount` (`xfs_vfsops.o`, +0x1738) does: `vfs_lock(vfsp)`; `xfs_mount(vfsp, mvp, uap, cr)`;
`vfs_unlock(vfsp)`; returns the error. `uap` fields observed: `+0x0` special-file path (user ptr),
`+0x8` mount-point path (user ptr), `+0x10` flags (0x1 read-only, 0x2/0x4 select fs-type/data args,
0x20 remount), `+0x14` secondary flags, `+0x18` fstype (index or name pointer), `+0x20/0x28` data
pointer/length (zeroed by `fs_cover` when data flag 0x4 is clear).

### 4.4 xfs_mount and what it does (the part to wrap or reroute)

`xfs_mount(vfsp, mvp, uap, cr)` (`xfs_vfsops.o`, static, +0x14a8):
1. `cap_able_cred(cr, mount-capability)`; EPERM (1) if not.
2. `mvp->v_type == 2` (directory) else ENOTDIR (0x14).
3. Not remount: requires `mvp` not busy (count==1 test) else EBUSY (0x10).
4. `xfs_mountargs(uap, &args, 0)` (`+0x12d4`, global T): decodes the mount-data structure. Versioned
   `1..4` (`xfs_args_to_ver_1..4` converters); `xfs_cmountfs` rejects version outside `1..4` with EINVAL.
5. `spectodevs(uap->spec, &ddev, &logdev, &rtdev)` (`+0x284`, static): `lookupname`; requires `v_type==3`
   (block device) else ENOTBLK (0xf); `dev = v_rdev` (vnode+0x24); calls `volume_get_devts(...)` to split
   an XLV/XVM volume into data/log/realtime devs; for a plain disk all of ddev/logdev = dev, rtdev = 0.
6. `vfs_devsearch(ddev)`: EBUSY (0x10) if that device is already mounted (unless update).
7. `xfs_cmountfs(vfsp, ddev, logdev, rtdev, flags=2, &args, mvp?, cr?)` (`+0x418`, global T) — does all the real work.

`xfs_cmountfs` (high level, observed): bail if `vfs_flag & 0x10`; `mp = xfs_get_vfsmount(vfsp,ddev,...)` which does
`xfs_mount_init()` then `vfs_insertbhv(vfsp, &mp->bhv, &xfs_vfsops, mp)` and sets `vfs_fstype (+0x34) = xfs_fstype`,
`vfs_dev (+0x20) = ddev`, `vfs_flag |= 0x1020`; opens each device: `make_specvp(dev, VBLK)` then **open via the spec
vnode's behavior ops slot +0x8** (VOP_OPEN); `xfs_fill_buftarg(&mp->targ, dev, vp)` (see Q6);
`xfs_readsb(mp, ddev)` (the superblock read+validate, Q5); then version-dependent checks; `xfs_mountfs(vfsp, mp, ddev)`;
`spec_mountedflag(vp,1)`. On error it closes devices with ops slot +0x10 (VOP_CLOSE), `binval(dev)`, `vn_rele`.

### 4.5 Intercept candidates, ranked

All three are live-patchable; none need a table rebuild.

**BEST: the MOUNT slot of `xfs_vfsops`, i.e. the 8-byte function pointer at `xfs_vfsops+0x8`
(initial value `xfs_vfsmount`).** Reasons (all observed):
- It is DATA, a single aligned 8-byte store, no instruction patching or I-cache concern.
- Called exactly once per new XFS mount, from `fs_cover`, after the dnlc purge, with a fresh unattached `vfs_t`
  (no XFS state created yet: no `mp`, no behavior, no devices opened), so rerouting leaves no cleanup debt.
- Failure path is the caller's: `vfs_deallocate(newvfs)`; returning an errno is a clean refuse.
- Other vfsops slots are looked up per-vfs through the behavior that the mounting module inserts with `vfs_insertbhv`.
  A wrapper that, for a v5 superblock, hands the mount to the new module (which itself calls
  `vfs_insertbhv(vfsp, &its_bhv, &its_vfsops, its_mp)` and sets `vfs_fstype`/`vfs_dev`/flags exactly as
  `xfs_get_vfsmount` does) makes later unmount/sync/statvfs/root dispatch to the new module with no further patch.
- Not used on remount (`+0x18`), unaffected. Root-mount slots (`+0x10`, `+0x50`) are separate and unaffected.

Wrapper contract: `int wrap_mount(vfs_t *vfsp, vnode_t *mvp, struct mounta *uap, a3, cred_t *cr)`.
It must itself resolve `uap->spec` to a dev (what `spectodevs` does: copy-in-path, `lookupname`, require VBLK,
`v_rdev`), read 512-byte block 0 (Q5/Q6 for how), inspect `sb_versionnum & 0xf`: if `<= 4` tail-call the saved original
`xfs_vfsmount`; else call the new module's mount. `xfs_vfsmount` itself is a global `T` and `xfs_spectodevs`-equivalent is
file-static (`t spectodevs`), so the wrapper must reimplement the device resolution (or call `lookupname` + `volume_get_devts`).

Alternate A: the `vfssw[xfs_fstype].vsw_vfsops` pointer (entry+0x10) -> point at a router `vfsops` object. Equivalent
effect, but needs a full replacement vfsops (copy of `xfs_vfsops` with slot 0x8 changed); slot patch is simpler.

Alternate B: `getvfsops` (static `t`, `fs_subr.o`+0x554) is the only place that turns an fstype into ops
before any vfs state exists, but it only sees `uap`, needs a code patch at its single in-object caller
(`fs_cover`+0xf0) and file-static call sites. Not recommended.

Do NOT intercept inside `xfs_readsb` / `xfs_mount_validate_sb`: they are file-static callees, run after XFS has already
allocated `mp`, inserted its behavior and opened the devices, and can only return an error, not reroute.

### 4.6 Registering a brand-new fstype at runtime (relevant to a toolchest module)

`mload.o` has a built-in "file system" loadable-module class (`fsys_*`, `filesys_check`, `filesys_init`, `filesys_insert`).
Observed:
- `filesys_check(mod)`: needs a non-empty name (prefix), else error 0x5e; scans `vfssw[1..vfsmax-1]` with `strcmp`;
  duplicate name -> error 0x5f ("filesystem already exists in vfssw table"). Allocates a slot via `fsys_alloc()`;
  none free -> 0x32. Stores the index at `mod+0x14`.
- `filesys_init(mod)`: `mversion_chk`; mallocs a 0x11-byte name copy from the prefix; resolves, from the module's own symbols by
  suffix, **`<prefix>init`**, **`<prefix>vfsops`**, **`<prefix>vnodeops`**, and optionally `<prefix>unload`
  (errors 0x3f / 0x3d / 0x3e name which of init/vfsops/vnodeops is missing; lboot's strings say "No xxxinit found",
  "No xxxvnodops found", "No xxxvfsops found"). Builds a 0x30 entry `{name, init, &vfsops, &vnodeops, dead_vnodeops, 0}`, calls
  `init(&entry, index)`, then `filesys_insert` copies it into `vfssw[index]` with `bcopy(0x30)` under `vfsswlock`.
- Therefore a module registering as fs type name N must export: `N_init(struct vfssw*, int)`, `N_vfsops`, `N_vnodeops`.
  This is the supported path; the type then becomes reachable from `mount -t N` through `getvfsops`/`vfs_getvfssw`.
  (Whether the shipped kernel is configured to allow loadable fs modules on a given IP35 build is unverified: the
  `system.dl`/`master.d` `d`/`R` flags for fs types were not checked beyond noting `xfs` is statically linked, flags `oxj`.)

## Q5. Where XFS reads and validates the superblock; what a v5 superblock trips

### 5.1 Read path (observed)

`xfs_readsb(mp, dev)` (`xfs_mount.o`, +0x460, global T; its only caller is `xfs_cmountfs`; `xfs_mountfs_int` also uses it):
1. `bp = ngetrbuf(0x200)` : a private, non-cached raw buffer with a 512-byte data area.
2. Sets `b_blkno = 0` (+0x90), `b_edev = dev` (+0x50), `b_flags |= B_READ(1)` (+0x10),
   `b_relse = xfs_sb_relse` (+0xb0), `b_target = mp->m_ddev_targp` (+0x60, from mp+0x1f8).
3. `xfsbdstrat(mp, bp)` then `iowait(bp)` (= `biowait`).
4. Error: `xfs_ioerror_alert` (unless EINTR-class 0x13), `nfreerbuf`, return the errno.
5. OK: `xfs_mount_validate_sb(mp, (xfs_sb*)bp->b_addr /*+0x80*/)`; nonzero -> `nfreerbuf`, return it.
6. Success: `mp->m_sb_bp (mp+0x118) = bp`; **copies exactly 0xd0 (208) bytes** raw, in 8-byte steps, from the buffer to
   `mp+0x40` (the in-core `m_sb`); `brelse(bp)`. No byte-swapping (big-endian host == on-disk big-endian).

Consequences: IRIX reads exactly ONE 512-byte basic block at disk block 0 of the data device, whatever
`sb_sectsize` says. The in-core superblock is only 208 bytes. Anything past offset 0xd0 (v5 `sb_features_compat`,
`sb_crc`, uuid-meta etc.) is never read, never copied, never checksummed.

### 5.2 The version-good check: `xfs_mount_validate_sb(mp, sbp)`

`xfs_mount.o`, +0x25c, static `t`, 0x204 bytes. Only caller: `xfs_readsb` (+0x514). `sbp` is the raw
on-disk-layout superblock (offsets below are the standard published big-endian XFS superblock layout; consistent
with every access in this routine). Returns `0` ok, `0x3f3` (1011, "wrong filesystem" class) for version rejects,
`0x3f2` (1010, "corrupted" class) for geometry rejects (these call `xfs_corruption_error`/`xfs_error_report` with source line numbers
0xc3/0xd6/0xe3/0xf5 first).

Checks in order (all widths as loaded):

A. Magic: `lw [sb+0x00] == 0x58465342` ("XFSB"), else 0x3f3.
B. Version (`lhu [sb+0x64]`, 16-bit `sb_versionnum`, unsigned):
   - `versionnum == 0` -> 0x3f3.
   - `versionnum < 4` (signed compare of a zero-extended value): accepted with NO further feature checks (old v1-v3 superblocks).
   - `versionnum >= 4`:
     - `(versionnum & 0xf) != 4` -> 0x3f3. **THIS IS THE v5 TRIP.** A v5 superblock has low nibble 5.
       Also trips any future nibble (6+).
     - `(versionnum & 0x0800) != 0` -> 0x3f3. (bit 0x0800 = the "sector size" feature bit in the published
       Linux numbering; IRIX 6.5.30 refuses it.)
     - if `(versionnum & 0x8000) != 0` (the "more bits" bit; `features2` valid): `lw [sb+0xc8]` (`sb_features2`)
       `& ~0x1b != 0` -> 0x3f3. So only features2 bits 0x01, 0x02, 0x08, 0x10 are tolerated; anything else, e.g. bit
       0x80 (project quota 32), 0x100 (CRC), 0x200 (ftype) rejects.
     - `lbu [sb+0xb3]` (`sb_shared_vn`) `> 0` -> 0x3f3 (shared-version feature unsupported when nonzero).
     - Other versionnum bits (0x10 attr, 0x20 nlink, 0x40 quota, 0x80 align, 0x100 dalign, 0x200 shared, 0x400 logv2,
       0x1000 extflg, 0x2000 dirv2, 0x4000 borg) are NOT rejected by this routine in 6.5.30.
   Note for v5: a v5 superblock also sets 0x8000 and has nonzero features2 in practice, so there are several
   independent rejections, but the very first is the nibble test. All return 0x3f3.
C. Geometry (reached for `versionnum` 1..3 and for accepted v4):
   - If `sb_logstart [sb+0x30]` (8 bytes) == 0 (external log): `mp+0x1c0 == mp+0x1d8` (the data and log device numbers
     taken from the mount) -> 0x3f2 (external log but same device).
   - `sb_blocksize [sb+0x04]` == 0, `sb_agcount [sb+0x58]` == 0, `sb_sectsize [sb+0x66] <= 0` -> 0x3f2.
   - `sb_blocklog (lbu [sb+0x78])` must be in `9..16` inclusive -> else 0x3f2.
   - `sb_inodesize (lhu [sb+0x68])` must be in `0x100..0x800` inclusive -> else 0x3f2.
   - `sb_blocksize * sb_rextsize [sb+0x50]` (32-bit multiply): `> 0x40000000` or `< 0x1000` -> 0x3f2.
   - `sb_imax_pct (lbu [sb+0x7f]) >= 0x65 (101)` -> 0x3f2.
   - `sb_dblocks (ld [sb+0x8]) == 0` -> 0x3f2.
   - Consistency: `(zero-extended agcount) * sb_agblocks(lwu [sb+0x54])` must be `>= dblocks`, and
     `(agcount-1)*agblocks + 0x40` must be `<= dblocks`, else 0x3f2. (64-bit multiplies.)
   - `sb_inprogress (lbu [sb+0x7e]) != 0` -> 0x3f2 via `xfs_error_report` (mkfs/growfs was interrupted).
D. Nothing else: no CRC/checksum, no uuid check here (uuid handled later in `xfs_uuid_mount`), no inode-size/blocksize/inopblock
   cross-checks, no v5 field reads.

After `xfs_readsb`, `xfs_cmountfs` (`+0xad8`) re-reads in-core `versionnum & 0xf` and branches only on `== 4` (v4 path tests the "shared"
bit 0x200 for clustered mounts; sector-size and log-buffer-size mount-arg checks). `xfs_mountfs_int` branches on
`(m_sb.versionnum & 0xf) == 4` for v4-specific setup (quota bits, `features2` handling) and checks `sb_inodesize` against
{256,512,1024,2048} for its btree geometry. None of that is reached for a v5 superblock; it dies in validate_sb.

### 5.3 Net answer, "what does a v5 superblock trip"

Mount fails in `xfs_readsb` -> `xfs_mount_validate_sb` with errno 0x3f3 (1011) at the `(sb_versionnum & 0xf) != 4` test.
`xfs_cmountfs` then frees the sb buffer (`nfreerbuf`), closes the devices, returns 0x3f3 to `fs_cover`,
which `vfs_deallocate`s and returns it to `mount(2)`. Nothing is written to the disk. A module that reads sector 0 itself
and inspects `[sb+0x64] & 0xf` (value 5) before XFS touches it sees the same field IRIX tests.

6.5-base cross-check: the older `xfs_mount_validate_sb` (6.5-base IP30 `xfs.a`) used a mask `versionnum & 0xffffec00`
(rejects 0x400, 0x800, 0x2000, 0x4000, 0x8000) and had no features2 test. Low-nibble `== 4` test and `shared_vn` test
identical. So the nibble test is stable across both releases.

## Q6. Block I/O and buffer-cache interface for a new filesystem module

All names are exported symbols (T) from `sgi.a:fs_bio.o`, `sgi.a:chunkio.o`, `os.a:pda.o`, `specfs.a`. Parameter
meanings are from XFS call sites and the callee bodies.

### 6.1 Two caches

1. **Buffer cache** (`fs_bio.o`): buffers indexed by `(dev, blkno, length)`; used by XFS for metadata (superblock, AG headers,
   btrees, inodes, log). Unit of `blkno` and `len` on the API = 512-byte basic blocks ("BB"). In `get_buf` the byte length is
   `len << 9`, stored in `b_bufsize` (+0x68). Hash: `_bhash(dev, blkno)` into `global_buf_hash` buckets; match test
   is `b_edev(+0x50) == dev && b_blkno(+0x90) == blkno && b_bufsize(+0x68) == len<<9`.
2. **Chunk cache** (`chunkio.o`): per-VNODE, page-backed cache of file data, indexed by file offset. XFS uses it
   for file contents via `chunkread`, `getchunk`, `chunkrelse`, `chunkpush`, `chunkreread`, `chunktoss`,
   `chunkinvalfree`... The chunk buffer is a `buf_t` whose `b_vp` (+0x88, label) points to the vnode's behavior. To do the
   disk I/O the cache calls the FILE'S vnode op **strategy (ops slot +0xf8)** with the chunk buf (seen in `cread` and
   `bwrite`), and the filesystem's `strategy` maps via its own block-map and issues the device I/O.
   Block map is obtained through the vnode op **bmap (ops slot +0xf0)**.
   A new fs that wants page-cache semantics for file data should provide `bmap` and `strategy` vnode ops and use the chunk calls;
   a fs that only needs raw metadata I/O can use the buffer cache alone. Direct I/O is separate (`biophysio`/`getphysbuf` plus the fs's own
   strategy, `xfs_diostrat`).

### 6.3 Lifecycle (observed)

Allocate/lock + read:
- `getblk(dev, blkno, len)` = `get_buf(dev, blkno, len, 0)` (`fs_bio.o`, +0x1f70 / +0x2010): look up in hash; if found, try to lock
  (`cpsema`); with flags bit0 set return NULL instead of sleeping; else allocate from free list. Returns a LOCKED buf
  (psema'd). `B_DONE` set in `b_flags` means contents valid.
- `bread(dev, blkno, len)` = `read_buf(dev, blkno, len, 0)` (+0x870/+0x88c): `bp = get_buf(...)`; if `B_DONE` return it (clears b_target);
  else `b_flags |= B_READ`, resolve the driver table entry for `dev` (`MAJOR[]` -> `bdevsw[]`, or `hwgraph_bdevsw_get(dev)` if major bits are 0),
  `bdstrat(bdevsw, bp)`, then `biowait(bp)`; return `bp`. **Caller must check `geterror(bp)`**.
- `read_buf_targ(targ, blkno, len, flags)` (+0x9d0): same, but device = `targ->dev (+0x10)`, driver = `targ->bdevsw (+8)`, and records
  `bp->b_target = targ (+0x60)`. XFS wraps it as `xfs_read_buf(mp, targ, blkno, len, flags, &bp)` (+0x6b7c): returns errno from
  `geterror`; on error alerts (`xfs_ioerror_alert`) and may `brelse`.
- `breada`, `baread` exist for read-ahead. `incore(dev, blkno, len)` peeks without allocating.
- Private non-cached buffers: `getrbuf(flag)`, `ngetrbuf(bytes)` (= `getrbuf` + `bio_realloc(bp, bytes)`, sets `b_bufsize`), `freerbuf(bp)`, `nfreerbuf(bp)`,
  `geteblk`/`ngeteblk` (empty block-cache buffers). The raw-buffer API is what XFS uses for the superblock read.

Write/release:
- `bwrite(bp)` (+0x1300): synchronous unless `0x100` (async) set. Dispatch order: if `b_vp (+0x88)` set -> that vnode's strategy op (ops slot 0xf8);
  else if `b_strat (+0xd0)` set -> call it; else `bdstrat` via `b_target`/`dev`. `xfs_bwrite(mp, bp)` sets `b_mount` and `b_strat = xfs_bdstrat_cb` first,
  and on error calls `_xfs_force_shutdown`.
- `bdwrite(bp)`: delayed write (mark dirty, release; the `bdflush` daemon (`bdflush`, `bflush`) pushes). `bawrite`: async write.
- `brelse(bp)` (+0x1dd0): on release, if `b_relse (+0xb0)` is non-NULL and bit 0x40000 of `b_flags` is clear the hook is invoked instead of the
  normal free-list put; otherwise clears the error, puts on the free list (`bfreelist`) and `vsema`s the lock. Always `brelse` every buf you got from `bread/getblk`.
- Completion: `biodone(bp)` (driver side), `biowait(bp)` (= `iowait`; `psema(bp+0xb8)` then `geterror`), `iodone` = `biodone`. Error API: `bioerror(bp, errno)` (sets
  `b_error` and `B_ERROR(4)`), `geterror(bp)` (returns `b_error` if `B_ERROR` else 0; EIO (5) if error flag set with zero code).
- Invalidate: `binval(dev)` (+0x46c4), `binval_dev`, `bflush_dev`.

### 6.4 How XFS issues I/O to the disk driver

- Device handle: `xfs_buftarg` (my label) = 3 words: `{ vnode* (spec vp), struct bdevsw* , dev_t dev }` filled by
  `xfs_fill_buftarg(targ, dev, vp)` (`xfs_vfsops.o`, +0x358): `targ+0x10 = dev`, `targ+0x0 = vp`, `targ+0x8 = bdevsw`, where bdevsw =
  `bdevsw[MAJOR[ext_major(dev)]]` (bounded by `bdevcnt`/`bdevmax`) or `hwgraph_bdevsw_get(dev)` when the external major field is 0.
  (`dev_t` external major = bits 18..26: `(dev >> 18) & 0x1ff`.) `mp` holds three: `mp+0x1b0` (log? / label), `mp+0x1e0`, `mp+0x1f8`
  (data device `m_ddev_targp`, used by `xfs_readsb`). Exact assignment of `mp+0x1b0/0x1c8` (log/rt) is from `xfs_get_vfsmount` zero-init and
  `xfs_cmountfs`; not fully labelled.
- Open: `make_specvp(dev, VBLK(3))` (`specfs.a:specsubr_local.o`) then the spec vnode's behavior ops slot +0x8 (VOP_OPEN) with the mode, close = slot +0x10.
  `spec_mountedflag(vp, 1)` marks it mounted. `binval(dev)` flushes stale cache.
- Strategy call: `xfsbdstrat(mp, bp)` (`xfs_rw.o`, +0x6d34) -> if grio enabled and the buffer qualifies -> `griostrategy`/`grio2strategy`, else
  `bdstrat(bp->b_target->bdevsw, bp)` (`os.a:pda.o`, +0x159c).
- `bdstrat(bdevsw, bp)`: if `bdevsw == NULL` or its flag word (`*bdevsw->d_flags`) bit 0x10 (stub) is set -> `bioerror(bp, 0x3f0 or 6)`, `biodone`,
  returns error. Otherwise bumps a per-CPU stat, optionally `bp_dcache_wbinval` when the driver lacks the "writeback-ok" flag (bit 0x8, master `w`)
  and cache write-back is configured, takes the driver lock (`bdrv_lock`), calls **`bdevsw->d_strategy`** (function pointer at `bdevsw+0x20`) as `d_strategy(bp)`,
  unlocks (`bdrv_unlock`). Driver completes with `biodone(bp)`.

### 6.5 What a NEW filesystem module must provide

To register as a type (Q4.6): export `N_init(struct vfssw *, int fstype)`, `N_vfsops`, `N_vnodeops`; at mount time (`N_vfsmount`, vfsops +0x8)
resolve the device, open it via `make_specvp` + open op, fill a buftarg-like handle, `bread`/`read_buf_targ` metadata, then:
`vfs_insertbhv(vfsp, &bhv, &N_vfsops, pdata)`; set `vfsp->vfs_fstype (+0x34)`, `vfs_dev (+0x20)`, `vfs_flag |= 0x1020`; return a root vnode from the vfsops root slot;
supply `vnodeops` (below). Use `fs_*` generic stubs (`fs_nosys`, `fs_noerr`, `fs_noval`, `fs_nodev`, `fs_cmp`, `fs_poll`, `fs_frlock`, `fs_pathconf`,
`fs_cover`, `fs_vnode_change`, `fs_tosspages`, `fs_flushinval_pages`, `fs_flush_pages`, `fs_invalfree_pages`, `fs_pages_sethole`, `fs_dounmount`,
`fs_realvfsops`) for slots you do not implement.

Calling convention for vnode ops: first arg is the behavior descriptor (`vp+0x60` head, ops at `bhv+0x10`, `[bhv+8]` = vnode); this is how
`cmount`, `cread`, `bwrite` and `xfs_cmountfs` call them (`ld ops,0x10(bhv); ld fn,slot(ops); jalr fn`). A vnode is created with
`vn_alloc`/`vn_get` and given the behavior via `bhv_desc` + your vnodeops (not decoded here; `dead_vnodeops` is the placeholder).
`vfsops` table as in 4.3 (note the first word header and the trailer magic 0x18732739 with values 1 and 2).

**Unmount / lifecycle obligations observed in XFS (copy these):** on unmount close the devices (open-slot counterpart at ops+0x10),
`binval(dev)`, `vn_rele` spec vnodes, `spec_mountedflag(vp,0)`, free the buftarg state; write dirty metadata with `bwrite`/`bdwrite` and flush
(`xfs_syncsub`).
