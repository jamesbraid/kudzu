# Routine roles: IP27 control-call handlers

Role statements for control-call entries of the 6.5.30 IP27 kernel that the request tables in [driver-ioctls.md](../driver-ioctls.md) do not cover (that page reads IP30). The control flow, the callees, the capability bits and the return values are the facts of [ip27-kernel-io.md](../ip27-kernel-io.md), where each routine was read from the 6.5.30 IP27 binary. Addresses are those of `6.5.30/unix.IP27`.

- `pcibr_ioctl` in `6.5.30/unix.IP27` at 0xc0000000000715b8
  **Established.** The control-call entry of the PCI bridge. It takes the connection point of the vertex in `a0` with `hwgraph_connectpt_get`, keeps the bridge record from `hwgraph_fastinfo_get` at sp+32 and drops the vertex with `hwgraph_vertex_unref`. Then it compares the request in `a1` with 26369 (0x6701), 26370 (0x6702), 28673 (0x7001), 28674 (0x7002) and 28675 (0x7003). Any other request returns 0. The user pointer in `a2` is kept at sp+40. Requests 0x6701 and 0x6702 both test capability `1 << 37` with `cap_able` at 0xc00000000028741c and return 1 when it is denied; both then copy 16 bytes from the user pointer (a failed copy returns 14). A word from that copy goes to `pcibr_device_slot_get` at 0xc000000000071530, and a result of 255 returns 5. For 0x6701 the copy lands at sp+16, the slot word is the word at sp+16 and the decision word is the doubleword at sp+24. For 0x6702 the copy lands at sp+0, the slot word is at sp+0 and the decision word at sp+8. A zero decision word returns 0. A nonzero one calls `pcibr_priority_bits_set` at 0xc000000000074a2c with the fast-info pointer, the slot masked to a byte, and a2 = 1 for 0x6701 or a2 = 0 with a3 = 255 for 0x6702, and then returns 0. The call is conditional on the decision word being nonzero. The callee's name suggests priority bits for the slot, and nothing else in the routine says what those bits are. Requests 0x7001, 0x7002 and 0x7003 call nothing and check no capability; each returns 1.
