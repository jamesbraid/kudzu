# Driver control requests: IP30 kernel dispatch

Request dispatch of control-call entries in the IRIX 6.5.30 IP30 kernel (`6.5.30/unix.IP30`, a linked 64-bit MIPS big-endian ELF). Each entry gives the request values the routine tests, the path each one takes, the callee for every step, and the size of the user buffer it copies. Addresses are virtual addresses in that image. "Request" is the second argument of the entry (`a1`). Grades follow [AGENTS.md](../../AGENTS.md#2-evidence): **established** means the whole routine body for that request was read; **inferred** means part of it was matched by name or call only.

The other builds (IP27, IP35) are not covered yet.

## PCI bridge

- `pcibr_ioctl` (`6.5.30/unix.IP30`, address 0xa8000000200432b8, occupies 368 bytes, 80-byte frame): **established.** The control-call entry of the PCI bridge's character device. Arguments: `a0` the bridge vertex, `a1` the request (kept in `s0`), `a2` the user pointer (saved at sp+40). Every request first resolves the vertex with `hwgraph_connectpt_get` (0xa80000002023de6c), takes the bridge's soft record from `hwgraph_fastinfo_get` (0xa80000002023d638) and drops the vertex with `hwgraph_vertex_unref` (0xa80000002023c3a8). The record is kept at sp+32. Then the request is compared with the five values below. Any other value returns 0.
- Request 26369 (0x6701): needs the capability bit 1 << 37 through `cap_able` (0xa80000002022e9bc); when it is denied the routine returns 1. It then copies 16 bytes from the user pointer into the stack buffer at sp+16 with `copyin` (0xa800000020017010); a fault returns 14. The word at buffer +0 is passed to `pcibr_device_slot_get` (0xa800000020043230). A result of 255 returns 5. Otherwise, if the doubleword at buffer +8 is zero the routine returns 0; if it is nonzero it calls `pcibr_priority_bits_set` (0xa80000002004652c) with the record, the slot masked to 8 bits, and 1, and returns 0.
- Request 26370 (0x6702): the same capability check, the same 16-byte copy (into the buffer at sp+0) and the same slot test (255 returns 5). It differs in the last step: the doubleword at buffer +8 is tested the same way, and a nonzero value calls `pcibr_priority_bits_set` with 0 as the third argument instead of 1. It returns 0.
- Requests 28673 (0x7001), 28674 (0x7002) and 28675 (0x7003): return 1 at once. They call nothing and check no capability.
- Any other request: returns 0 with no further call.

## SCSI host adapter

- `scsiha_ioctl` (`6.5.30/unix.IP30`, address 0xa80000002008db60, occupies 556 bytes, 112-byte frame): **inferred.** The control-call entry of the SCSI host adapter. Arguments: `a0` the controller vertex, `a1` the request (kept in `s0`), `a2` the user pointer (saved at sp+64) and `a4` the caller's credential word (saved at sp+56). The bit field `(a0 >> 18) & 0x1ff` is tested first: any nonzero value returns 6 with no call. Otherwise the routine calls `scsi_ctlr_info_get` (0xa800000020093fa0) on the vertex and keeps its result, the controller record, at sp+48. The request 29446 is tested after that call and before the allocation (see below). Every other request allocates a 16-byte zeroed buffer with `kmem_zalloc(16, 0)` (0xa8000000201486a4) and keeps it at `s1`; the paths after that are in the entries below. The routine frees the buffer with `kern_free` (0xa8000000201488f0) on every path that reached the allocation.
- Request 29446 (0x7306): does not allocate. It resolves the vertex with `hwgraph_connectpt_get` (0xa80000002023de6c) and passes that to `device_controller_num_get` (0xa80000002018ca2c). A negative controller number releases the vertices with `hwgraph_vertex_unref` and returns 0. The rest of this path builds a hardware-graph path (`hwgraph_path_to_dev`, `hwgraph_traverse`, `hwgraph_edge_add`, `hwgraph_path_add`); it is not read in full. The negative path reads the word at sp+0 for its first unref. That word is stored only at 0xa80000002008dc70, which that path has not reached, so the unref takes a stale stack value (the store is at 0xa80000002008dc70 and the load at 0xa80000002008dcfc). **Inferred.**
- Request 29473 (0x7321): it copies 16 bytes and runs the ABI step as the requests of 11 and above do (below), then calls `cap_able_cred` (0xa80000002022e8f0) with the credential word and 1 << 37. A denied capability returns 1. A granted one calls the controller record's routine at record +40 (see the generic request below). **Established.**
- Requests below 11: no copy. The routine calls the record's routine at record +40 with `a0` the word at record +0, `a1` the request, `a2` the zeroed buffer, and returns its result. **Established.**
- Requests 11 and above other than 29446 and 29473: `copyin` copies 16 bytes from the user pointer into the buffer. A fault frees the buffer and returns 14. On success, `get_current_abi` (0xa8000000203aa9fc) is called and bit 2 of its result is tested. When bit 2 is clear, the doubleword at buffer +8 is replaced by its upper word, shifted down 32 bits. Then the routine calls the record's routine at record +40 with the same arguments as above and returns its result. **Established.**
