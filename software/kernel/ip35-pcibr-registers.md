# Bridge register accessors in the IP35 pcibr object

Register accessor routines of the PCI bridge driver, read from the object `6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o` (an ELF object whose `.text` offsets are given as addresses). Each accessor takes the bridge as its first argument in one of two forms: the soft state, whose halfword at +114 selects one of four register layouts and whose doubleword at +8 is the register window, or the register window itself, recognised by the bits 63, 60 and 57 all being set, in which case the widget id word at window +4 selects the layout. The layouts are numbered here by the soft-state value: 3 and 2 use 64-bit registers, 0 and 1 use 32-bit ones. The accessors differ in the register they reach; the same layout test, the same range assertions that continue after a failure and the same unknown-layout panic wrap each of them.

**Views of the widget id word and the interrupt address registers (established for the instructions).** The registers sit in 8-byte slots on a big-endian machine, so a 32-bit register is the low word of its slot, reached at slot +4. The widget id word is therefore the 32-bit word at window +4 (`pcireg_control_get`, `lw` at displacement 4 of the raw window pointer, address 0xc0000000000acaa8 in `6.5.30/unix.IP35`), which is the low half of the register at window +0; a register list that counts slots shows it as a 4-byte access at 0x0. The interrupt address register of pin n is a 32-bit word at 0x134 + 8n on the two 32-bit layouts (`pcireg_intr_addr_get`, `lw` at displacement 0x134, address 0xc0000000000b2870 of the same kernel) and a doubleword at 0x130 + 8n on the two 64-bit layouts (`ld` at displacement 0x130, addresses 0xc0000000000b28ec and 0xc0000000000b28fc). The same two instruction forms are in `6.5.30/unix.IP27` (`pcireg_control_get` 0xc00000000007f0cc, `pcireg_intr_addr_get` 0xc000000000084e94 and 0xc000000000084f10). Bits 11:1 of the widget id word are the manufacturer number in the public Linux crosstalk widget header (v5.3, `arch/mips/include/asm/xtalk/xwidget.h`), which gives 54 to the first bridge and 36 to the later one; the pairs the kernel accepts match those values (inferred, since the kernel names no field). `defs/pcibr.toml` in the chips repository states the same views.

- `pcireg_wrb_flush_get` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 596 bytes at address 0x171b0): reads one device's write-response flush register from a PCI bridge and returns what it holds.
  `a0` is the bridge and `a1` the device number (kept in `s0`). A null `a0` panics. If `a0` has bits 63, 60 and 57 all set (the mask 0x9200000000000000 formed by `li at,-55` and `dsll32 at,at,25`) it is the register window itself, and the layout comes from the widget id word at window +4: part number (bits 27:12) 0xe000 or 0xe010 with the 11-bit field (bits 11:1) equal to 36 selects the first 64-bit layout, 0xd102 or 0xd112 with 36 the second, 0xd002 with 36 or 0xc002 with 54 the 32-bit layout; any other id panics. Otherwise `a0` is the soft state, whose halfword at +114 selects the layout (3, 2, or 0 and 1 together; -1 panics; any other value skips the read and returns 0) and whose doubleword at +8 is the window. Both 64-bit layouts read the doubleword at window + 576 + 8 x device, after an `assfail` check at line 2506 (first layout) or 2510 (second) that the device is 0 to 3; the 32-bit layout reads the word at window + 580 + 8 x device (zero-extended with `dsll32` and `dsrl32`), after a check at line 2515 that the device is 0 to 7. A failed device check falls through and the read goes ahead anyway. The value read is tested on every path: nonzero calls `assfail("ret == 0", file argument not copied, 2523)` and the value is returned either way. The panics use "pcireg_wrb_flush_get(): unknown bridgetype" and return 0. The frame is 32 bytes and no instruction is branch-likely. Established.
- `pcireg_type0_cfg_addr` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 688 bytes at address 0x1879c): computes the address through which a device's type 0 PCI configuration register is reached.
  `a0` is the bridge (soft state or register window, decoded as in `pcireg_wrb_flush_get`), `a1` the slot, `a2` the function and `a3` the register offset. On the 32-bit layout (soft kind 0 or 1; ids 0xd002 or 0xc002) it checks the slot is 0 to 7 (line 2933) and returns window + (slot << 12) + (function << 8) + offset + 0x20000; on the two 64-bit layouts (kinds 3 and 2) the slot is first incremented and masked to a byte, checked to be 1 to 4 (lines 2920 and 2928), and the same sum is formed with that incremented slot. In every case the offset is first rounded toward zero to a multiple of four (add 3 when negative, `sra` 2, `dsll` 2). A failed slot check does not stop the computation. A null bridge, soft kind -1 or an unknown id calls `panic("pcireg_type0_cfg_addr(): unknown bridgetype")` and returns 0, and an unlisted soft kind returns 0 without a message. The frame is 48 bytes and no instruction is branch-likely. Established.
- `pcireg_int_ate_get` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 620 bytes at address 0x19184): reads one internal address-translation entry of the bridge.
  `a0` is the bridge, `a1` the entry index (kept in `s0`). The layout is chosen as in `pcireg_wrb_flush_get`, but here the soft kinds 0 and 1 differ: kind 0 (id 0xc002) allows indexes 0 to 128 (assert string at line 3081) and kinds 1, 2 and 3 allow 0 to 1024 (lines 3077, 3073 and 3069, in that order). The result is the doubleword at window + 0x10000 + 8 x index, the same on every layout; a failed range check is reported and the load still happens. A null bridge, kind -1 or an unknown id calls `panic("pcireg_int_ate_get(): unknown bridgetype")` and returns 0. The frame is 32 bytes and no instruction is branch-likely. Established.
- `pcireg_int_ate_set` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 620 bytes at address 0x193f0): writes one internal address-translation entry of the bridge.
  `a0` is the bridge, `a1` the index and `a2` the value (kept in `s2`). The same decoding and range limits as `pcireg_int_ate_get` apply, with different assert lines: 3112 for kind 0 (0 to 128), 3108 for kind 1, 3104 for kind 2 and 3100 for kind 3 (each 0 to 1024). The store is `sd` of `a2` at window + 0x10000 + 8 x index on every layout, after the check whether it passed or not. Nothing is read back and no result is set. A null bridge, kind -1 or an unknown id panics with "pcireg_int_ate_set(): unknown bridgetype", and an unlisted soft kind does nothing. The frame is 32 bytes and no instruction is branch-likely. Established.
- `pcireg_int_ate_addr` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 596 bytes at address 0x1965c): returns the address of one internal address-translation entry instead of reading it.
  `a0` is the bridge and `a1` the index (kept in `s0`). Layout choice and limits match `pcireg_int_ate_get`: kind 0 allows 0 to 128 (assert line 3143), kinds 1, 2 and 3 allow 0 to 1024 (lines 3139, 3135 and 3131). The value returned is window + 8 x index + 0x10000, built with `daddu` and `lui 1`, and nothing is loaded from it. A null bridge, kind -1 or an unknown id calls `panic("pcireg_int_ate_addr(): unknown bridgetype")` and the result is 0; an unlisted soft kind also returns 0. The frame is 32 bytes and no instruction is branch-likely. Established.
- `pcireg_device_bit_set` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 564 bytes at address 0x16d40): sets bits in one device's control register of the bridge.
  `a0` is the bridge, `a1` the device (`s0`) and `a2` the bit mask (`s2`). Layout choice as in `pcireg_wrb_flush_get`. On the 32-bit layout it ORs the mask into the word at window + 516 + 8 x device (`lw`, `or`, `sw`; device checked 0 to 7 at line 2456); on the two 64-bit layouts it ORs it into the doubleword at window + 512 + 8 x device (`ld`, `or`, `sd`; device 0 to 3, checked at line 2447 for the first and 2451 for the second). A failed check is reported and the update still happens. There is no result. A null bridge, kind -1 or an unknown id calls `panic("pcireg_device_bit_set(): unknown bridgetype")`. The frame is 32 bytes and no instruction is branch-likely. Established.
- `pcireg_device_bit_clr` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 572 bytes at address 0x16f74): clears bits in one device's control register of the bridge.
  Arguments and layout choice are those of `pcireg_device_bit_set`. The mask in `a2` is inverted with `nor` against zero and ANDed into the register: the word at window + 516 + 8 x device on the 32-bit layout (check at line 2483, device 0 to 7) or the doubleword at window + 512 + 8 x device on the 64-bit layouts (checks at lines 2474 and 2478, device 0 to 3). The check does not stop the update. The unknown-layout panic text is "pcireg_device_bit_clr(): unknown bridgetype". The frame is 32 bytes, no result is set, and no instruction is branch-likely. Established.
- `pcireg_intr_addr_vect_set` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 572 bytes at address 0x1592c): sets the interrupt vector field of one PCI interrupt's destination register.
  `a0` is the bridge, `a1` the interrupt number (`s1`, checked 0 to 7 at line 2139) and `a2` the vector, kept at sp+0. The two 64-bit layouts load the doubleword at window + 304 + 8 x n, clear bits 55:48 with a mask from the pool at .lit8 +176 (0xff00ffffffffffff), store it, load it again, OR in `a2 & 0xff` shifted left 48 and store again. The 32-bit layout does the same on the word at window + 308 + 8 x n, clearing the low byte (AND with -256) and ORing in `a2 & 0xff`. A failed range check falls through to the update. The unknown-layout panic prints the text of the matching read routine, "pcireg_intr_addr_vect_get(): unknown bridgetype", not its own name. No result is set. The frame is 48 bytes and no instruction is branch-likely. Established.
- `pcireg_intr_addr_addr_set` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 588 bytes at address 0x15d98): writes the target address part of one PCI interrupt's destination register.
  `a0` is the bridge, `a1` the interrupt number (checked 0 to 7 at line 2202) and `a2` the address, saved at sp+0. On the 64-bit layouts it clears the low 48 bits of the doubleword at window + 304 + 8 x n (AND with 0xffff000000000000), stores that, reloads it, ORs in `a2` masked to its low 48 bits and stores again. On the 32-bit layout it clears bits 17:8 of the word at window + 308 + 8 x n (AND with the .lit8 +184 pool value 0xfffffffffffc00ff), stores, reloads it and ORs in `(a2 >> 30) & 0x3ff00`, so only address bits 47:38 are kept. The layout is chosen as in `pcireg_wrb_flush_get`. The unknown-layout panic prints "pcireg_intr_addr_addr_get(): unknown bridgetype", the name of the read routine. No result is set. The frame is 48 bytes and no instruction is branch-likely. Established.
- `pcireg_intr_addr_addr_get` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 560 bytes at address 0x15b68): reads back the target address of one PCI interrupt's destination register.
  `a0` is the bridge and `a1` the interrupt number (checked 0 to 7 at line 2171). On the 64-bit layouts it returns the doubleword at window + 304 + 8 x n ANDed with 0x0000ffffffffffff. On the 32-bit layout it returns the word at window + 60 (zero-extended) ORed with a value shifted left 32 whose bits are the low six bits of the word at window + 52 together with bits 17:8 of the word at window + 308 + 8 x n shifted right two, so address bits 47:38 are rebuilt from the entry and bits 37:32 and 31:0 come from the two shared words. The layout is chosen as in `pcireg_intr_addr_addr_set`. A null bridge, soft kind -1 or an unknown id calls `panic("pcireg_intr_addr_addr_get(): unknown bridgetype")` and returns 0, and an unlisted soft kind returns 0. The frame is 32 bytes and no instruction is branch-likely. Established.
- `pcibr_error_intr_handler` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 1460 bytes at address 0x9bb4): handler for a PCI bridge's own error interrupt, as built into the pcibr object.
  Its 363 instruction words, compared one by one with the linked kernel's copy at 0xc0000000000a7274, are the same except for 54 whose operands the linker fills in: call targets, gp-relative loads of the string pool, the `lit8` masks and the globals. One callee has a different name: the object calls `test_and_set_long` where the kernel's symbol for the same code is `test_and_set_int64`. `a0` is the bridge soft state (`s0`). The routine first looks `a0` up in the global list `pcibr_list` (next pointer at +0, soft pointer at +8) and panics with "pcibr_error_intr_handler: (0x%lx) is not a pcibr_soft!" (.rodata 0x1d80) when it is absent. It calls `hubii_check_widget_disabled` with a node number from bits 39:33 of the doubleword at soft +8 and the byte at soft +40; a nonzero answer calls `timeout`, adds one to the word at soft +2104 and returns. Otherwise it reads the status with `pcireg_intr_status_get`, logs it through `pcibr_debug` with mask 0x100, and returns when no bit from 8 up is set. Status bits in 0x0000004400008800 (.lit8 +104) first call the static routine at 0x9a4c. Each set bit n from 8 to 63 (bit 31 excepted) bumps a 12-byte record at soft +2276 + 12 x (n - 8) and may log a rate warning through `cmn_err` at level 4 or 5, or clear enable bits under the lock at soft +140 with `pcireg_intr_enable_bit_clr`. When bit 24 is set, `pcireg_bus_err_get` ANDed with 0xffffffffffc00000 equals 0xc00000 and `pcireg_cmdword_err_get` ANDed with 0xf07f00 equals 0x402000, bit 24 is dropped. The global `bridge_errors_to_dump` is then ORed with the .lit8 +104 mask when `pcibr_pioerr_dump` is nonzero and ANDed with 0xffffffbbffff77ff when it is zero; a surviving bit prints "BRIDGE ERR_STATUS 0x%lx\n" at level 6 with `pcibr_error_dump`, and for the bits of the mask at .lit8 +128 `machine_error_dump` and `panic("PCI Bridge Error interrupt killed the system")` follow. The reset written back with `pcireg_intr_reset_set` is `pcibr_errintr_group(status)` for soft kinds 0 and 1 and the status ORed with 0x40 otherwise. It finishes by calling `test_and_set_long` with the address soft +2120 and zero. Branch-likely instructions are at 0x9d90, 0x9e14 and 0xa02c. The kind-2 revision test around `pcireg_arbitration_bit_set` and the per-bit rate arithmetic were not traced to the end here. Inferred.
- `pcibr_dmamap_pciaddr_get` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 8 bytes at address 0x3a9c): returns the doubleword at offset +56 of a DMA-map record. It is a return instruction with the load in its delay slot and has no frame or conditional path. Established.
- `pcibr_flags_to_ate` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 180 bytes at address 0x4c88): converts bridge mapping flags in `a0` into an address-translation-entry control word. It starts with 0xb, changes or clears bits 0x10, 0x8 and 0x4 according to input bits 0x10, 0x20, 0x400 and 0x800, and tests input bits 8 through 15 by sign after left shifts to set or clear the corresponding low control bits. It returns the constructed word in `v0`, reads no memory and has no frame. The meaning of the individual flag bits is unknown from this routine alone. Established.
- `pcibr_flags_to_d64` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 428 bytes at address 0x2228): converts bridge mapping flags in `a0` and bridge state in `a1` into a 64-bit DMA descriptor control word. It selects fields from input bits 4, 5, 6, 7, 8, 9, 10, 11, 12 and 13, applies layout-specific masks, and uses the halfword at bridge state +114 and bit 0 at +116 to choose the register layout and one final mode bit. An unsupported combination of the initial bit 6 path calls an unresolved diagnostic helper before continuing. The result is in `v0`; the frame is 32 bytes and no store is made. The meanings of the encoded fields are unknown here. Established.
- `pcibr_thread_setup` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 120 bytes at address 0x7854): records a caller-supplied halfword at offset +72 of the bridge state, atomically ORs 0x300 into the word at offset +40, and invokes two relocated helper calls with the bridge state and the recorded value. It uses a 64-byte frame, retries the `sc` until it succeeds, and returns the result of the second helper call. The effects of the two helpers are not established by this body. Established.
- `pcibr_disable_mst_timeout_work` (`6.5.30/usr/cpu/sysgen/IP35boot/pcibr.o`, occupies 84 bytes at address 0xeb48): calls three relocated bridge helpers, passing the bridge state to the first and third and a relocated constant address to the second. It returns 0 when the first and third results compare equal and 1 otherwise; it performs no direct load or store beyond its 32-byte frame. `pcibr_enable_mst_timeout_work` at 0xeb9c has the identical control flow and frame, with the same unresolved helper roles.
